Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

- **Folders find their ancestor.** A worktree, a clone, a scratch or task folder is almost always part of a project, so the curator no longer judges each folder on its own. Code now looks for the project a folder belongs to: the git worktree or clone it was (recorded while the checkout existed), paths in its facts that sit inside a project's tree or its worktrees folder, a name that contains a project's name, and sessions it shares with a project whose files its facts point at. A folder related to a project is taken as part of it. It stands on its own only on evidence of its own identity: its own commits, its own remote or GitHub repository, or sessions working in a folder of its own name. The curator has to cite that evidence, and code refuses it otherwise. A worktree that git's records place is folded by code alone. Folders that share an ancestor are decided in one batch. On three copies of the Mac's shadow store, three of the four task folders that v0.9.2 folded differently from run to run now go to the same project every time (kvstore into agent-lab, worktree into tacit, wt-portfolio-rework-20261004 into portfolio). valkey-review-bot, which v0.9.2 always left for review, is now its own active project, on its GitHub repository. Three folders for which code finds no ancestor still differ from run to run, and so does park-predictor. A repository with its own commits and its own remote can no longer be folded into a project only because its name contains that project's: one of the runs did that, and this release refuses it.
- **The dreamer remembers worktrees and clones.** From now on each linked worktree and separate clone a session works in is recorded with its repository, and git's own list of a checkout's worktrees is read too. When the worktree is removed, its sessions and any folder named for it still land in the right project. Each machine's catalog in the store carries the worktree and clone names, never their paths.
- **MCP servers update themselves.** A `tacit mcp` server started by an agent session used to keep running the old binary after an upgrade, reading the store with old code. It now checks at each request whether the binary on disk changed. When it has, it finishes the requests in flight and restarts itself in place on the same connection, keeping the session, so the agent notices nothing. On Windows, which cannot do that, every tool result says the server is outdated and how to reconnect.
- **`tacit doctor` lists tacit processes on an outdated binary,** on Linux and macOS, with their command lines and what to do.

Upgrading: nothing to do. MCP servers already running from an older release don't update themselves; reconnect them once (in Claude Code: `/mcp`, then reconnect tacit), and `tacit doctor` lists any that are left.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
