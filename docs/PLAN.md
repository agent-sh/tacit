# Plan

This is the build plan tacit was made by, kept as its design history: each decision with its date, each phase with the proof that closed it. Measurements are in `eval/VALUE.md`; the store contract is `SPEC.md`.

Decisions (2026-10-07): the server runs on an always-on host on the tailnet, not on the workstation, which is not always on; a push mirror and backups of the store are the operator's choice; the curator runs daily with the configured model; the dreamer runs every few hours with its configured model and its cost is measured before it is accepted; Elixir for the server, Go for the client. Hooks fired at SessionStart and UserPromptSubmit only, with no per-tool-call hooks until a metric showed a need; the 2026-10-21 replay did (eval/VALUE.md, "Repo-first delivery"), and a PreToolUse hook pushes at most one matching fact per edit or command.

## Scope (decision, 2026-10-09)

A survey of open-source agent memory (Hindsight, ai-memory, The Librarian, mem0, Graphiti, Letta, Cognee, Honcho, mcp-memory-service and others) found the store, server, hooks, MCP and transcript mining are common, and nothing open does the source-grounded pair verifier, protected owner rulings or the measured delivery. Decision: tacit is the one fact store for every harness, its commodity layers are frozen (no new storage or retrieval features unless a measurement asks), and harness reach reuses existing hook surfaces before writing new ones.

## Git as a source (decision, 2026-10-10)

Git is a main source of tacit's knowledge, not a side input. Facts are checked against git wherever a repo backs them. Git marks hot areas, shows how a decision moved, and holds measured results. For results (bench numbers, eval scores) git is often more correct than what an agent saved, and newer commits often replace older results that a saved fact still quotes. This direction is outside the 2026-10-09 freeze.

Trust rule: git is evidence for what happened, when, and what a number was. The committer is usually an agent (the main session or a subagent), even when the author identity is the owner's, so a commit is never an owner ruling. Git can retire an agent-saved observation; it can never retire a ruling (`source.kind: user` or `type: user_standard`). A conflict with a ruling goes to the owner.

Steps, each with its proof:
1. **Timeline evidence per pair.** A reusable package builds a dated timeline for two facts: their own dates (frontmatter and store history) and the repo commits that touched their subject (paths, symbols, terms), plus the state at HEAD. The verifier gets it as primary evidence and the review page shows it under each pair. Proof: on the owner's labelled sample, the verifier with the timeline agrees with them more often than without it (median of 3 runs) and retires no more facts the owner kept. Result (2026-10-10, PR #18, eval/VALUE.md): the package and the review-page display shipped; on the sample2 labels the verifier with the timeline did not agree more often (median 19 of 27 in both arms over 10 paired runs), so `tacit verify` does not send it. The page is where the timeline helps the owner.
2. **Derived facts.** Hot spots with co-change partners and a module map per repo, from git (PR #15). Proof: a known memra hot spot appears without anyone writing it.
3. **Staleness check.** The daily curator lists curated facts whose subject changed in git after the fact's last update and sends them to the verifier with their timeline. It flags, it does not retire on its own. Proof: a fact made stale by a later commit in a fixture repo is flagged; an untouched one is not. Built 2026-10-10 (`tacit stale`, `client/internal/stale`, the last step of `tacit curate`; contract in SPEC.md "Staleness check"; `eval/VALUE.md`). Result: the first rule, a changed line holding a name the fact states, was right for 0 of 16 hand-checked flags (the name still stood at HEAD: a reworded doc, a refactor, a generic flag in another tool's docs), while 4 of 4 flags raised by a deleted file were stale. The shipped rule flags only deletions: a named file gone from HEAD, or a named identifier removed after the fact's date and held by no file of the repo. On the real store, day one flags 21 of 4688 facts (1938 have a git trace); by hand 18 of the 21 have something stale (11 should retire, 7 need a detail fixed) and 3 are still true. A repo is read at its default branch (a stale checkout hid 5 of them), by committer date, and a read that did not finish flags nothing and is retried with backoff. A changed value whose name stands is not flagged: not a deletion, and it is left to the page's timeline until a value-aware rule is measured (step 4 reads committed results). The check flags; the verifier retires an agent-saved observation (a new `retired:` date, not a successor fact) and never an owner ruling, which becomes a question. Sonnet 5.5 on 13 non-ruling flags of the first version matched the hand labels on 12 (median of 3 runs) and never retired a fact the labels kept, $0.13 to $0.18 a run.
4. **Results from git.** Measured results committed to repos (row logs, JSON boards, tables in results documents) become facts that carry the commit sha. A newer result for the same metric and setup replaces the older one, and an agent-saved fact quoting the older number is flagged (`result-superseded?`, one pair for the verifier and the owner). Built 2026-10-10 (`client/internal/results`, `tacit results`, a pass of `tacit curate`; contract in SPEC.md "Results from git"). Read deterministically: a free-text model path was measured (Haiku 5.5 on 1089 commit messages, 96.7 percent right on a hand-checked 30, but only 1.3 percent of the metric-and-setup groups hold two values from two commits and those are sibling arms) and left out. A git read that fails or is cut never retires a fact; a result never retires an owner ruling; the review page never patches the generated side of a pair. A result fact is printable by the prompt hook only when it is a row log or a group a curated fact quotes (type `result`); every other group is type `result_ref`, found by search and the MCP tool, never printed by the hook (measured on 52 prompts: on the reviewer's 21 the hook printed 17 result lines before this gating, 8 helpful, 5 weak and 4 wrong by hand, and 8 after, 4 helpful, 4 weak and 0 wrong; eval/VALUE.md). Proof: fixture repo tests (two committed results for one benchmark end as the newer in the store with the older shown as replaced; a saved fact quoting the older value is flagged; a different setup, a dated record, a threshold, a fact that states both values and a one-digit number are not; a failing git read removes nothing; an owner ruling becomes a `RULING CHANGE?` line and is never edited; secret redaction before name and clip, fail closed; lint clean); extraction checked on 30 random real rows (30 of 30 hold the value at the cited line or JSON path and at the writing commit); on the live store 14 curated facts quote 19 current rows and none quotes a replaced value, so the first real flag is still to come; the real-history reproduction flags one constructed fact against real perf-ci history (`eval/VALUE.md`, "Results from git").
5. **Decision trail.** A decision fact can list the commits that introduced, changed or reversed it, so the review page and the verifier see how it moved. Proof: a reversed decision in a fixture repo shows both commits and the verifier keeps the current side.

## Architecture

- **Server** (Elixir 1.20 / OTP 28, Plug.Router + Bandit + phoenix_pubsub, no Phoenix): owns the bare store repo. Git smart HTTP by driving `git upload-pack` / `receive-pack --stateless-rpc` through Exile. Writes take a per-repo FIFO lease: spool body, receive-pack, diff refs, append `{seq, sha}` to a SQLite journal, release, rebuild index, broadcast `{:head_moved, seq}`. `receive.autogc=false`, gc under the same lease. Pre-receive validates (lint, secrets, key scope). Bound to the tailnet IP; identity via tailscaled LocalAPI WhoIs; Ed25519 request signatures with public keys committed in the store under `keys/`. Off-tailnet gets 403.
- **Change feed**: SSE, "notify, don't carry": each client replays the journal from its `Last-Event-ID` seq. Keepalive comments; 60 s poll as the client fallback.
- **Client** (Go 1.27, one binary `tacit`): hooks (`hook session-start`, `hook prompt`), `search`, `fact`, `add`, MCP stdio server, `dream`, `curate`, `lint`, `index`, `import`, keys. Measured hook cost 28 to 42 ms warm, so the stdlib-only hook binary and the unix-socket daemon were not needed; sync happens at SessionStart with an 8 s budget unless `tacit follow` (the SSE client, a systemd user service) has just confirmed the clone current, in which case the hook skips it (SPEC.md "Change feed"). Shell out to `git` with process groups and http timeouts; `go.yaml.in/yaml/v3` strict; `modernc.org/sqlite` FTS5.
- **Dreamer** (per machine, every X hours, configured model): cursor per transcript file and per harness memory file; digests the delta deterministically (same code as `eval/mine/digest.py`), then one request per session delta under 100K tokens: review what Codex (native memories), Claude (auto-memory dir) and Hermes (skills) wrote, dedupe against the store, classify, fill `applies_to`, and extract facts nobody wrote. Output to `inbox/dreamer@<host>/`. Metered: tokens, cost, facts emitted, later promoted vs rejected.
- **Curator** (daily, configured model): `tacit curate` in the Go client, run by a systemd user timer on a machine with model access (the server has no model credentials, which decided its location). Split, ruling preservation, contradiction and supersession checks against the index, `review/<date>.md`, `MEMORY.md`, lint, push as `curator@<host>`. The Elixir server stays the authority and transport.
- **Index**: client-side SQLite FTS5 (`~/.local/state/tacit/index/index-<sha>.db`, built on first use after a sync, bm25 with name and description weighted 6:6:1 over body). No embeddings: dense retrieval measured below lexical on both the raw and the curated store (eval/VALUE.md section 5).
- **Retrieval order**: scope first (the session's repo and host, plus system and user), then the prompt text as the query at UserPromptSubmit; at SessionStart the repo and host names are the query. `applies_to` as emitted by models is too generic to rank on (measured); its paths and commands are matched, not ranked, by the prompt hook's metadata line and the PreToolUse hook (2026-10-21).

## Layout

```
system/               always loaded, small, reviewed
user/                 who the owner is, standards, voice
projects/<repo>/      decisions, past mistakes, history
machines/<host>/      hardware, paths, what is dead on this box
derived/<repo>/       hot spots with co-change partners, module map; generated from git, derived_from: <sha>
inbox/<harness>@<host>/<slug>.md        raw, unreviewed, append-only
MEMORY.md             generated from frontmatter
eval/                 truth set, baseline, results
```

## Phases

Each step lists what proves it done. A step without its proof is not done.

0. **Truth set and grep baseline.** `eval/truth.jsonl` with at least 20 items in each of three fact types; `eval/BASELINE.md` with the grep number, reproducible from the pinned corpus manifest.
1. **Schema and import.** `SPEC.md` (layout, frontmatter, `applies_to`). `tacit lint` fails on the current auto-memory dirs and passes after import. `tacit import claude|codex` puts every existing fact in `inbox/import@<host>/` with provenance; nothing is hand-placed in `curated/`.
2. **Server.** Elixir release on the server host (bound to the tailnet IP only, WhoIs identity; TLS is WireGuard's). Done 2026-10-08: `server/deploy/proof.sh` enrolls the workstation's key, clones over the tailnet, pushes into `inbox/claude@<host>/`, is refused outside it, reads the journal and the feed, and the public address does not answer. The server refuses to enroll or authenticate a key id whose harness is not on its list (`server/lib/tacit_server/auth/key_id.ex`; a test fails when it differs from the client's list or SPEC.md). `state.db` needs no backup: it holds the journal and replay nonces, the nonces are worth nothing after two token windows, and the journal is rebuilt at every start from the reflog of `main` (exact order, push boundaries and writer) or, when the reflog is gone, from first-parent history (exact order, one row per commit); a journal that is behind, damaged or off the repo is repaired or set aside the same way. The unit is sandboxed (no capabilities, AF_UNIX/INET/INET6 only, system call allow list, no W+X memory, private /dev and /tmp, hidden /proc of other users), checked against a built release; exposure score 7.1 down to 1.4. The hook keeps no log (the journal and the unit log cover accepted pushes). Tests added for gzip push, the 64 MiB and 10 MiB caps, protocol v2 info/refs, IPv6 and tagged-node peers, host mismatch, concurrent push order and the journal rebuild. Nothing in step 2 is open. Original proof text follows. Per-(harness,host) Ed25519 keys enrolled via tailnet identity; a key may push only to its own inbox dir; `curated/` accepts only the curator key. Proof: a client push to `curated/` is rejected at pre-receive. Pre-receive lint and secrets scan; proof: a fact containing a token is rejected with the reason.
3. **Client, dreamer, curator.** Done 2026-10-08 on the workstation (PR #4): hooks installed (SessionStart on startup only, 10 facts, rules first; UserPromptSubmit 3 facts above a score floor, once per session, nothing on harness-injected turns), Codex MCP registered, `tacit dream` on a 4 h timer, `tacit curate` daily. The SSE feed client is done 2026-10-10: `tacit follow` holds `/events`, syncs each burst of pushes (fetch into a private ref without the store lock, merge under it, reindex), resumes from a saved seq, reconnects with jittered backoff (1 to 60 s), checks the clone against the server every 5 minutes, and keeps a heartbeat in `~/.local/state/tacit/follow.json`; `tacit install follow` writes its systemd user unit, and with a fresh heartbeat SessionStart skips its network sync (workstation, load 47, three runs each: 381 ms, range 363 to 391, without; 31 ms, range 16 to 31, with). Proof for a second machine: `tacit clone` plus `tacit install claude` there, a fact pushed from it appears on the first after `tacit sync`.
4. **Retrieval.** Done 2026-10-08: client-side FTS5 keyed by HEAD, bm25 with descriptions weighted over bodies; dense retrieval (EmbeddingGemma 2) measured below lexical and dropped; applies_to not a ranking input (measured). Rerankers not pursued: the store, not the ranker, was the bottleneck (`eval/VALUE.md`).
5. **Curator.** Daily job with the configured model under the `flock` holder in a worktree, commits as `curator@<host>`: dedupe, merge, supersede, absolute dates, fill `applies_to`, promote inbox to curated, generate `derived/<repo>/` (hot spots, co-change, blame age, module map, `derived_from: <sha>`), regenerate `MEMORY.md`, lint. Proof: the imported inbox from step 1 becomes a curated tree and lint passes; a known memra hot spot appears without anyone writing it. Review ledger: the owner reviews the curator's diff summary; a rejection reverts and becomes a `user_standard` fact. Derived facts built 2026-10-10 (`client/internal/derive`, `tacit derive`, wired into `tacit curate`; contract in SPEC.md "Derived facts"): per repo with a curated `projects/<repo>` scope and a checkout, one hot-spot fact (top 10 files by commits over the last 400 code commits, co-change partners inline) and one module-map fact, no model call, read at the branch the machine's config names (`tacit derive --set-branch`, for example `sglang=dev`) or the remote default branch of the checkout, after a 30 s one-branch fetch that moves only the remote-tracking ref (else HEAD, recorded), same commit gives the same bytes, a repo whose commit did not move is not touched, vanished repos are retired by the host that produced them. Computed in memory and written under the store lock after a sync (an interrupted run leaves the clone clean, one refused repo does not stop the others); names outside a conservative character set are left out and counted. Proof run against the real memra checkout (dry run into a scratch dir, not the store): `memra-hot-spots` lists `crates/memra-server/src/worker.rs` (35 of the last 400 code commits), `crates/memra-engine/src/lib.rs`, `.github/workflows/ci.yml` and `dsv4_gpu.rs` with the files that change with it, and nobody wrote it. 39 of the 95 project scopes have a checkout and got facts in 19 to 44 s on the loaded workstation. Delivery: never at SessionStart; the prompt hook adds at most one, from its own query, after the curated facts (`eval/VALUE.md`, section "Derived facts"). Still open: blame age as a fact (decided against, see SPEC.md), a first live run on the server, an eval of whether the facts save tool calls.
6. **Rollout and measurement.** The workstation is done. Measurement done in `eval/VALUE.md`: live hooks score 0.69 on owner-ruling decisions against 0.64 bare and 0.73 oracle, tool calls 123 against 134, 3 reps judged. Still to do: more machines (`tacit clone`, `tacit install claude`, keys enrolled); the dreamer's cost per promoted fact over a real week.
