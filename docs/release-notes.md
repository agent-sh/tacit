Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

- **Active or dormant comes from dates, the same in every run.** Whether a project is being worked is a question of dates, and dates can be checked, so code now answers it instead of the curator. Before the curator sees a folder, code gathers every date it can check: your commits in a checkout here, other machines' catalogs, the sessions that worked in the folder or filed its notes, and the newest 100 commits on GitHub with who made them (a bot's commits are shown, not counted). Code measures the folder's own rhythm, the typical gap between your stretches of work on it, and calls it active while you have been away less than twice that gap, never less than a week and never more than 32 days. Those bounds come from your own history on the Mac's shadow store: half of your breaks are a week or less, and 80% end within 32 days. An archived repository is never active. Before, GitHub's commits reached the curator only when it asked about a folder a second time, so whether a run saw your latest commit depended on how its first answer went. On three copies of the Mac's shadow store, each run until nothing was left to assess, the statuses that differed from one run to the next went from 19 in v0.9.3 to 4, and none of the 4 is about dates: each is whether a folder is a project of yours at all (a fork, an upstream clone, two folders with nothing of their own).
- **Dead and shipped need evidence, never dates.** The curator still decides what a folder is and which project it belongs to. It may call a folder dead only on explicit evidence it cites: GitHub has the repository archived or deleted, a note shown for it says it was removed, or your own words. Shipped needs a release, package or deploy together with your statement or decision. Without that, code keeps its own status and says why in the record. Your own status is never replaced.
- **Code keeps statuses current.** When the dates move a project past its window, code writes the new status itself, without asking the model.
- **Re-attempts search wider, not differently.** A folder left for review is asked again with the store's other facts that name it, the sessions behind them, decisions on similar folders and your words. GitHub's record is no longer part of that, since every first ask already has it.

Upgrading: nothing to do. The first assessment after the upgrade asks GitHub about each project's repository once (three read-only calls each, kept a day), so it takes a few minutes longer.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
