Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

This release fixes three faults on the curator's machine, each one a run that failed or a finding that could never be settled, and the daily platform smoke.

- **A rulings answer with a sentence before it is sent back.** For a note with no owner words, the curator's rulings pass is asked for every ruling the split missed, and there is none. Asked for "a JSON array (possibly empty)", Opus 5.5 explained the empty answer first ("The note quotes no owner words, so there are no rulings to extract. []") on 52 of 110 calls. Code refused the answer whole and did not send it back, so a note alone in its batch failed the run: from 03:33 on 10-30 every quick curate that took the newest note exited 1. The prompt now says the empty answer is `[]` and nothing else (0 of 110 had a sentence). The rulings pass also sends an answer that is no JSON array, or does not parse, back to the model once, like one refused for its entries (52 of 52 came back clean). A second refusal still fails the batch. The method is `client/tools/envelope`.
- **A pair whose fact was replaced moves to the live facts.** The findings v0.9.15 named as stranded were pairs one of whose facts a third fact had replaced, so the verifier's "keep the other" was refused every time. Before it sends anything, `tacit verify` now follows each side of such a pair to the live fact at the end of its supersede chain. It closes the finding with a `moot` record and raises the pair of live facts as a new finding, which it verifies in the same run. When a side has no live successor, or both lead to one fact, the finding is just closed as moot, with the reason. Some findings are left alone: one the owner left a note on, and one whose chain runs through a supersede still under review, which waits for that review. A moot closure whose supersede is undone later is reopened. The page shows the record, and reopening it changes no fact.
- **Slack and Tailscale tokens take two steps, like `sk-`.** The server's secret scan took `tskey-` or a Slack prefix and any 10 letters, digits or hyphens for a key, so a fact name with such a segment (`tskey-auth-expires-in-90-days`) would refuse every curator push that named it. A token is now a key only when it holds what a real key has. For Slack that is an uppercase letter, a run of 20 letters and digits, a run of 10 digits, two 6-digit ids, or a legacy workspace token's version digit. For Tailscale it is an uppercase letter (a key id ends in `CNTRL`) or a run of 20. On 100,000 random keys of each shape every Slack and Tailscale key is refused. That now includes Slack's refresh, app-level, `xoxo-`, client session and session cookie tokens and webhook URLs, which the old rule let through. Names with such a segment go from about 99.4% refused to almost none. A blob with no such prefix skips the new steps, so a push costs what it did. The method is `eval/secrets/token_rules.py`.
- **The platform smoke runs again.** Since 10-22 the daily `portable client` run failed on every platform: the smoke started the browser app with `--no-open` on a pipe, which the app refuses because the page's link carries its token. The smoke is now its own browser opener and takes the link from there.

Upgrading: no index or store format change. An older binary reads what this one writes; its page shows a `moot` record as an answer. Deploy the server first for the new secret scan: an upgraded client's checks take the names an old server still refuses.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
