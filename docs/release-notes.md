Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

This release fixes three faults on the curator's machine. Each one held work back and said too little about it.

- **Curator pushes land again.** The server's secret scan took `sk-` and any 16 letters, digits, hyphens or underscores for a key. A fact whose name has an `sk-` segment (`lint-cc-sk-017-only-plain-commands`) is named in `MEMORY.md`, its folder's index and its own file, so every curator push after it was refused. An `sk-` token is now a key only when it holds what a real key has: an uppercase letter or underscore, a run of 20 letters and digits, or a lowercase UUID. A fact name has none of them, unless a 20-letter word follows its `sk-` segment. On 100,000 random keys of each shape (Anthropic, OpenAI project, service and legacy keys, DeepSeek, OpenRouter, Langfuse, LiteLLM, and unknown base64url keys of 20 to 48 characters) the new rule refuses all of them; a random 16-character key passes 1 time in 6,400. It refuses no fact name; the old one refused 97% of them. It never refuses what the old rule took. The scan runs on bytes in time linear in the blob, and a scan that fails now refuses the push instead of taking it. The method is `eval/secrets/token_rules.py` (then `sk_rule.py`).
- **A refused batch says why.** `tacit curate` printed only the files it set aside, an empty list for curated facts. It now prints the server's lines: `curate: server refused the batch: tacit: <path> looks like it contains a secret`.
- **Stranded verifier findings have names.** A finding the verifier failed on three times stopped being sent, and the run said only how many there were. Each counted failure is now recorded (redacted), the run names every finding at the limit with its last failure, and `tacit verify --requeue all` (or the ids) sends them again without a model call. One verify runs at a time (`verifier.lock`), so a run never writes its counters back over a requeue.
- **Scheduled jobs have a run limit.** A oneshot unit without `TimeoutStartSec=` waits forever. The dreamer, idle and local curate units and their Windows tasks now stop a run that outlives the run's own limits (2h30min, 2h30min, 5h). `tacit maintain` keeps none: verify has no overall budget, so no bound under its daily timer would be safe. Every git call already had a deadline; the client no longer passes `http.connectTimeout`, which git does not have. The optional store mirror's plain git gets the client's low-speed limit and a 10-minute bound.

Upgrading: no index or store format change. An older binary reads what this one writes. Deploy the server for the new secret scan. Run `tacit install dream` again to get the run limits.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
