Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

This release lets the owner or an agent keep one of two files that hold a name and retire the other. `tacit dedupe` raises such a name as a finding about the two files, the owner answers it on the review page, and an agent that can tell which file stands marks it with `tacit review apply`.

- **A name two files hold is raised for review.** Names are unique in a store, but a tool outside tacit can leave one name in two live curated files: a copy in a second folder. Findings, marks and questions are all keyed by names, so nothing in tacit could retire one of the two files as a copy of the other, or put the pair to the owner (#109).
  - `tacit dedupe` raises each such pair once, in `review/<date>-names.md`, the earlier file first. `tacit dedupe --names` raises them alone, retiring no copy and pointing no chain, and its `--dry-run` lists them.
  - The review page and tacit app show the two files side by side, each read by its path, with What git shows for both, as `tacit timeline ID` does. Keep one, and the other gets `superseded_by` the name, which then reads as the kept file; or keep both. The owner's reopen puts back what a mark changed, and their note sent with an answer names the two files. A name more than two files take part in takes no answer there: the page names the other files, and the owner retires the copies one by one.
  - An agent marks it with `tacit review apply`, naming the two paths as `a` and `b` and the one it keeps, with its evidence. The guards of every agent mark hold. No agent marks a finding that carries a mark or a question, that the owner marked or reopened, or whose name they kept in another answer. A mark that would retire their ruling or a fact with their words, or one on a finding or name they left a note on, becomes their question, and `owner` asks it outright. `tacit questions` lists the open ones, and `tacit questions close` does not take them. The verifier does not take them either, and the rotation leaves an open one's name out of its picks.
  - A copy retired into its own name ranks last among the name's curated files: in the lookup by name (`tacit_fact`, `tacit fact`, `tacit resolve`), on the review page and in tacit app, and in the overview step and the rotation. It never stands for the name again, whatever becomes of the file kept, and `tacit resolve` takes the name after a keep. The rulings audit gives such a copy no endorsement.
  - When another curated file holds a fact's name, tacit app acts on the fact by its path. Edit, Retire, Restore, Undo, This is mine, Not mine and Replace with a new rule change the file it shows.
  - Known gap: an agent's question on a name finding whose file later went away gets no moot record, and `tacit questions` stops listing it.

Upgrading: no index, store format or protocol change; the server needs no deploy. Install it on every machine that reads the store. The lookup by name is in the MCP server and the CLI, and an older client reads a copy retired into its name once the file kept is retired. An older client also shows no name finding in tacit app or on the review page, and its `tacit review apply` marks none. `tacit dedupe` is not a step of the daily run. To raise the names a store holds, run `tacit dedupe --names --dry-run`, then `tacit dedupe --names`, on the machine that writes as the curator; a later run raises only the new ones.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
