# tacit store specification

Version 1, 2026-10-07. This file is the contract between the Go client (`client/`), the Elixir server (`server/`) and the curator. Code follows this file; when they disagree, fix the code or change this file in the same PR.

## Local mode and client configuration

`tacit init [--store DIR]` creates a standalone store with `tacit.local=true` in repository-local git configuration. A populated directory or existing non-local repository is refused. Initialization builds a complete repository in a sibling staging directory, then publishes it. A new local store starts with the evidence-based ruling marker and an empty index; this initializes an empty store, not evidence for imported facts.

Local writes use the same file format, writer names and transaction locks. They commit only named files, leave unrelated staged work alone and run the server's obvious-token/private-key shape check before committing. Agent notes still pass through scrump first. There is no remote, enrollment requirement or server authorization boundary. Sync/fetch/integration and remote-ahead checks do no network work. Follow returns the non-restarting configuration status (78; translated to 0 under launchd) with an explanation. Server clones retain their existing behavior; network failure never selects local mode.

The optional client settings file is `~/.config/tacit/config.yaml` on Unix and the user's config directory plus `tacit/config.yaml` on Windows. `TACIT_SETTINGS` or the global `--config FILE` selects another file. Fields are `store`, `projects`, `index`, `keys`, `local_overlay`, `owner_names`, `verify_roots`, and `models` (`curate`, `judge`, `dream`, `verify`, `verify_fallback`). Relative paths resolve against the file. Environment values override file values; command flags override defaults. Unknown fields or a missing explicitly selected file fail before command work. Hook configuration failures print nothing and exit 0.

`tacit install curate [--env-file FILE]` installs the daily curation/verification sequence. `tacit maintain [--env-file FILE]` runs it manually. Linux uses a user timer, macOS a launchd agent, Windows a current-user Task Scheduler definition. Windows dreaming/following also use Task Scheduler. Installers write files and print start commands without registering or starting jobs. CLI/browser app builds support Linux, macOS and Windows; native-window builds remain optional on Linux/macOS.

## Two repositories

- **Code**: this repository. Client, server, curator, eval.
- **Store**: a separate private git repository holding the facts. Its authority is the server; a push mirror and backups are the operator's choice. It never goes to a public host. Each client's clone lives at `~/.local/share/tacit/store` (`$TACIT_STORE`).

## Store layout

```
system/                    always loaded; small; reviewed by the owner
user/                      who the owner is, standards, voice
projects/<repo>/           decisions, past mistakes, history for one repo
machines/<host>/           hardware, paths, what is dead on this box
derived/<repo>/            generated from git by the curator: hot spots with their co-change partners, module map (see Derived facts), measured results with their commit (see Results from git)
inbox/<harness>@<host>/    raw, unreviewed, append-only; subdirectories allowed
keys/<harness>@<host>.pub  Ed25519 public keys of enrolled writers; written by the server at enroll
review/<date>.md           curator findings for the owner: contradictions, supersessions, stale? checks and LINK? lines (dead links in rulings), appended per run
MEMORY.md                  generated index; never edited by hand
README.md                  optional, ignored by lint and index
```

`<harness>` is one of `claude`, `codex`, `pi`, `hermes`, `grok`, `muse`, `agy`, `dreamer`, `import`, `curator`, `human`, `reader`. `<host>` is the short hostname. A reader key only reads (see Public path).

## Ordering

The server keeps a journal: `seq` (monotonic integer), commit `sha`, `ts`, writer key. Every accepted push appends one row under the repo lease, so `seq` is the total order of the store. The change feed carries `seq`; clients resume from the last `seq` they saw. Git history is the content; the journal is the order. The journal is also recoverable: if the server loses it, it rebuilds from the reflog of `main` (one row per push, same order, same writer) or, without a reflog, from first-parent history (same order, one row per commit), and `seq` restarts at 1 in that order. A client resumes from the last `seq` it saw. If that `seq` is past the new head, the feed sends one `event: reset` frame carrying the head and continues from there; the client then does a plain `git fetch`.

Everything outside `inbox/` is **curated** and is written only by the curator. Agents write only under their own `inbox/<harness>@<host>/`. The server enforces both at pre-receive.

One fact per file. A file is Markdown with YAML frontmatter.

## Frontmatter

```yaml
---
name: memra-precommit-cargo-path          # slug, equals the file stem
description: one line, at most 200 chars  # what the index shows
type: past_mistake                        # see types
scope: projects/memra                     # see scopes
applies_to:                               # situation join key; any subset
  paths: ["tools/hooks/pre-commit"]       # repo-relative globs
  symbols: []
  repos: ["memra"]
  hosts: ["workstation"]
  commands: ["git commit", "cargo fmt"]   # prefixes
source:
  harness: claude                         # claude | codex | pi | hermes | grok | muse | agy | dreamer | import | curator | human
  host: workstation
  session: 7146f42d-...                   # optional
  kind: observed                          # user | observed | web | derived
  imported_from: ~/.claude/projects/.../x.md   # optional, import only
  original_type: feedback                 # optional, import only: the source system's own type
  owner_quote: "never push to main without a review" # kind user only: the owner's words the fact holds (see Rulings)
  owner_quote_from: claude:6f1c2a-...     # where the owner said them: claude:<session>, codex:<session>, note:<name>
  endorsed: 3f2a9c1d0e4b                  # kind user only: the decision in review/decisions.jsonl where the owner kept this fact
  owner_words: "keep the start block short" # any kind: a phrase of theirs the fact holds, too short to be a ruling (see Rulings, Their words)
  owner_words_from: claude:6f1c2a-...     # where the owner said them, as owner_quote_from
created: 2026-10-07                       # YYYY-MM-DD
updated: 2026-10-07
superseded_by: memra-precommit-path-fixed-in-hook   # optional, name of the newer fact
retired: 2026-10-12                       # optional, YYYY-MM-DD: outdated per git, no newer fact (see Staleness check)
derived_from: 3f2a9c1                     # derived/ only, git sha the aggregate was built from
origin: some-inbox-note                   # curator output only: the inbox note this fact was split from
---

Body: the fact, one to a few sentences another agent can act on. Optional
**Why** and **How to apply** lines. Link other facts as [[name]].
A [[name]] inside a fenced code block (``` or ~~~), an indented code block or an inline code span is
code, not a link: `fact.LinkSpans` skips it for lint L6 and for link repair.
```

### Types

`user_standard`, `design_decision`, `past_mistake`, `machine_fact`, `code_change`, `hot_spot`, `structure`, `history`, `user` (who the owner is), `reference` (pointer to an external system), `result` (measured numbers read from a repo's git history, generated; see Results from git). `unclassified` is allowed only under `inbox/`; the curator assigns a real type on promotion.

### Scopes

`system`, `user`, `projects/<repo>`, `machines/<host>`, `derived/<repo>`. A curated file's directory must equal its scope. Inbox files carry the scope the writer believes is right; the curator may change it.

### Source kinds

- `user`: the owner's own words, provably: a ruling (see Rulings). Every kind user curated fact carries the evidence.
- `observed`: an agent concluded it from what happened (an error, a measurement, a path that exists).
- `web`: derived from fetched content. Never allowed under `system/`; the curator promotes web facts only after review.
- `derived`: generated by the curator from git or other deterministic sources, no model involved; must carry `derived_from`.

## Rules the linter enforces

| id | rule |
|---|---|
| L1 | frontmatter parses; `name`, `description`, `type`, `scope`, `source.harness`, `source.host`, `source.kind`, `created` present |
| L2 | `name` equals the file stem and is a slug (`[a-z0-9][a-z0-9-]*`) |
| L3 | `type` is a known type; `unclassified` only under `inbox/` |
| L4 | curated file directory equals `scope`; an inbox path is `inbox/<harness>@<host>/...` with a known harness and a slug host, and the note's `source.harness` is that harness |
| L5 | `created`, `updated` are `YYYY-MM-DD` |
| L6 | every `[[link]]` in a curated fact names an existing fact (inbox links are the curator's to resolve on promotion; the curator repairs a curated fact's dead links, see Link repair) |
| L7 | `superseded_by` names an existing fact |
| L8 | no `system/` fact has `source.kind: web` |
| L9 | `derived/` facts carry `derived_from`; no other fact does |
| L10 | `MEMORY.md`, if present, equals the generated index |
| L11 | `description` is at most 200 chars; body is not empty |
| L12 | `source.kind` and `source.harness` are known values |
| L13 | `conflicts_with` names existing facts, never the fact itself |
| L14 | `retired` is `YYYY-MM-DD` and is not on an inbox fact |
| L15 | in a store the rulings audit has run on, a curated `source.kind: user` fact carries owner evidence (harness `human`, `owner_quote` with `owner_quote_from`, or `endorsed`); everywhere: `owner_quote` is in the fact's description or body (normalized, see Rulings), long enough to be looked up, and has its entry in `review/owner-quotes.jsonl`; `owner_quote_from` is a source and an id (`claude:`, `codex:` or `note:` today; any lower-case source name passes, so a ledger entry from a source no longer read stays valid); `endorsed` is a decision id that stands in `review/decisions.jsonl` as the owner's and keeps this fact; no `owner_quote` or `endorsed` on a fact that is not kind user; `owner_words` and `owner_words_from` go together, the fact holds the phrase, and the ledger has its entry marked words. Inbox notes may claim kind user without evidence: the curator decides |

The proof for the linter is that it fails on today's auto-memory directories (their `metadata` key is unknown to the strict decoder, and they carry no `scope` or `source`) and passes after `tacit import`.

## Supersede, never delete

A fact that turns out wrong or outdated gets a newer fact and `superseded_by` pointing at it. The old file stays. Retrieval excludes superseded facts by default; history queries include them.

A fact that git shows is outdated, with no newer fact to point at, gets `retired: <date>` (set by a staleness verdict, see Staleness check). Retired facts are treated like superseded ones everywhere: not indexed, not delivered, not searched by default, not counted as a live scope.

One exception: generated `derived/<repo>/` facts are removed, not superseded, when their repo leaves (see Derived facts). They hold no judgment, only a function of a checkout, and git history keeps the files.

## Contradictions

The curator checks every new fact against its closest existing curated fact and against same-scope facts of the same run in one batched judge call. A `supersedes` verdict is applied automatically only when the two facts come from the same inbox note or share most of their terms, and never against a ruling; every other verdict, and every `contradicts`, is a line in `review/<date>.md`. The owner answers with `tacit resolve`, which sets `superseded_by` or `conflicts_with` (frontmatter, lint L13, indexed; retrieval never delivers both sides of a `conflicts_with` pair). A second judge pass per batch lists owner rulings in the notes that the split did not produce as `kind: user` entries and adds them. Every `kind: user` entry of either pass goes through the ruling check (Rulings, The curator) before it is written. Nothing is deleted or silently merged. A batch whose conflict check cannot run (the index cannot be opened, or a query fails again after the index is opened anew) is not written: its notes stay pending and the run stops with a non-zero exit. `tacit curate --recheck-conflicts --since D [--until D]` runs the check again, alone, for the curated facts the split made in those days, each against its closest curated fact that is not newer than it, with the same verdict routes.

## Rulings

A ruling is the owner's own words, provably. Everything else, however it was filed, is an agent's statement: it is not labelled "your rule", and the verifier treats it like any observation (one that holds a few words of theirs is weighed by them: Their words, below). `fact.IsRuling` is the one definition, used by the hooks' `RULE` lines, the app and the audit, and the guard the verifier, the staleness check, the results step, the link repair and the curator's supersede check use. Nothing about rulings waits on the owner: the audit asks them nothing.

**The switch.** A store keeps its old definition (`source.kind: user`, or `type: user_standard`) until the rulings audit has run on it: the audit writes `review/rulings-audit.json` (version, the HEAD it audited, when; no list of facts) in its own commit, and `fact.Walk` reads it. With the marker a ruling is `source.kind: user` and one piece of evidence that the words are theirs:

- **Written by them**: `source.harness: human` on a curated fact (New rule in tacit app; only the app writes harness human facts and only the curator key writes curated ones), or a note in their `inbox/human@<host>/` that the app added: the commit that added it is one of the app's owner commits (`owner: ...`). The field and the directory alone are claims: `tacit add` and `tacit mcp` refuse harness `human` and `curator`, and lint L4 refuses an inbox note whose `source.harness` is not its directory's.
- **The owner's words, quoted**: `source.owner_quote` is a phrase the fact holds, found as a statement of theirs (below) in one of their turns or app notes, and `source.owner_quote_from` says where (`claude:<session>`, `codex:<session>`, `note:<name>`). The curator's quote ledger `review/owner-quotes.jsonl` records each (name, quote, where, a hash of their turn, the day); lint L15 requires the entry, so a claim the store does not back fails even after the transcript is gone.
- **Kept by them**: `source.endorsed` is the id of their standing decision in `review/decisions.jsonl` that keeps this fact: a pair the owner answered keep this one (`left` keeps A, `right` keeps B; a reopen clears it; an agent's record, `by: agent`, never counts), or `mine`, their "This is mine" in the app. L15 checks the decision stands and keeps this fact.

A field is only a claim: `fact.Walk` (and `fact.WithStore` for a fact read on its own) reads the ledger and the decision log, and a quote or an endorsement counts only when the store backs it. A forged `owner_quote` is no ruling and prints no `RULE`, whether or not anyone has linted. A marker that exists but cannot be read is an error (`fact.ErrMarker`): `Walk`, `WithStore` and lint fail rather than fall back to the old definition, which would turn every `user_standard` an agent filed into a rule no agent may touch, and every caller refuses to act (`tacit resolve` changes nothing, the link repair edits no fact). Evidence fields in a store with no marker are an L15 finding (only the audit writes them).

The type does not make a ruling: a `user_standard` with no evidence is the agents' reading of their preference.

**The owner's turns.** `internal/ownerwords` reads what the owner wrote themself on this machine:

- Claude Code transcripts, turn by turn: a user turn marked `origin.kind: human`, or, from a version that did not mark turns, one with no origin kind on a line whose own `entrypoint` is `cli` or `claude-desktop`. A turn another agent sent (`peer`, `task-notification`, ...), a line from a headless entrypoint (`sdk-cli`, `sdk-ts`), a compaction summary, a sidechain and harness text are not theirs; a slash command's arguments are.
- Codex sessions from a front end a person types into (`originator` `Codex Desktop`, `codex-tui`, `codex_cli_rs`, `codex_vscode`).
- The prompts the owner typed (`~/.claude/history.jsonl`, `~/.codex/history.jsonl`), which outlive the transcripts.
- The session digests of `eval/mine/digest.py` (`~/.cache/tacit-mine`), whose header names how the session started (`entry`); a subagent's digest (`--sub-`) is skipped.

Left out everywhere: sessions started where only agents start them (`/tmp` itself and below it, `/.claude/jobs/`, `/.cache/`, a scratchpad, an e2e driver, a runner's `/.local/runners/` checkout), a Codex message that is mostly a pasted table or log (six lines or more, half of them table rows or log lines; Codex keeps no record of pastes), text the owner pasted (the history's `pastedContents`, removed from the transcript's copy of the turn), a message that opens with a tag (`<task-notification>`, `<codex_delegation>`, `<synthetic>`, ...), Claude Code's notices, and an orchestrator's role prompt (a turn opening "You are ..."; the filters assume the owner writes in lower case). Inside their turns, agent text the owner relayed without a paste record is left out line by line: a markdown header, a line with a backtick or `**`, a bullet or numbered item opening with a capital, a backtick, `*` or `[`, and every line of a block of three or more capitalized prose lines (eight words or more, ending in `.`, `:` or `;`). The filter assumes the owner types plain lowercase lines in a terminal. On 2026-10-11 it dropped 982 distinct lines from 214 of 17,241 owner turns, and a random sample of 20 was all agent text. Agent prose the owner relays as plain lowercase lines is a known gap.

**Verbatim, and a statement.** Text is normalized before it is compared: lower case, apostrophes dropped (the owner writes "dont", an agent quoting them writes "don't"), every other character that is not a letter or a digit a space. A phrase is looked up from three words and 18 characters, on word boundaries; an ellipsis splits it into parts that must all be in one turn, in order. Quoted phrases are taken from double, typographic and guillemet quotes, single quotes at word edges, blockquote lines, and a clause the fact attributes to them without quote marks ("Owner 2026-09-05: <clause>.", or a name in `$TACIT_OWNER_NAMES` in place of "Owner"); a quoted command, path, flag or agent markdown is not one, and neither is such an attributed clause (`codeQuote`). A phrase is code when it holds a backtick, `**` or an assignment (`KEY=value`); when two code-like words (`--x`, `-x`, a path, `=`, `$`, `#tag`, `|`, `&&`) sit side by side; when it opens with a command (a sentence opening with "dont", "never" or "always" that names a command stays prose) (`gh`, `git`, `export`, `nice`, ...; after "run", "use" or "try" too), or a command is followed within three words by a code-like word, and it holds one; when a shell operator or loop runs through it (every word after `|`, `&&`, `#`, `; do` is code); or when it has fewer than six plain words, or fewer than two for each code-like one. So a sentence of theirs that ends "if the review passes you can merge with --squash" is a quote, and "run tacit rulings audit --recheck --push on the live store now" is not. One tolerance, because agents quoting them fix their typing: the same words in the same order where at most one word in four differs by one edit, a swap of two letters counting as one (two edits in a word of eight letters or more), never in a word under four letters, a number, a negation or a changed first letter, and never a word added, dropped or moved (`--strict` turns it off). A match counts only as a statement of theirs: not inside a question the owner asked (its sentence ends in a question mark and opens with a question word or with the words themselves) and not right after a negation of theirs ("never", "not", "dont" ... within three words, same sentence).

**Enough to be the rule.** A quote proves the fact is their ruling when it holds most (three fifths) of the content words of the fact's description, or has six words or more and shares one content word with the description or the fact's name (stopwords out, words cut to four letters; `ownerwords.ProvesRuling`). Length alone proves nothing. Six words of theirs with none of the rule's words ("this is not the place for old history" under an agent's cleanup checklist) are their words in the fact, not its rule. On 2026-10-11 this sent 7 of 29 paraphrased rulings of theirs to observed, with their words recorded: their quotes share no word with the rule as the agent wrote it, so no overlap gate keeps them and keeps an agent's lesson off. A request is never a rule (`ownerwords.Request`): a quote that opens with "can/could/would you", "please", "show me" or "give me", or with "i need/want" and a thing to be done ("i need the dashboard to show errors"), and holds no rule word (never, always, dont, only, must, should, every) and no condition (not, before, after, until, unless, any, if ...: "i need the tests to pass before any merge" is a standing condition, not a task). A quote the ledger holds that no longer passes stays their words, also once their transcript is gone. A shorter phrase of theirs ("what should we try next", a session's name) is theirs but may not be the rule the fact states, and so is a run of six of their words inside a quote whose rest an agent reworded: those facts carry their words as evidence (Their words) and stay agents' statements.

**The owner's words.** A fact with words of theirs too few to prove a ruling is `source.kind: observed` with `source.owner_words` (the phrase, which the fact holds) and `source.owner_words_from` (where, as for a quote), and a quote ledger entry marked `"words": true`. A words entry never backs an `owner_quote` (its key differs), so moving the phrase into `owner_quote` makes no ruling; L15 requires the entry, that the fact holds the phrase, and the pair. The words count (`fact.OwnerWordsOf`) only when the store backs them and no standing Not mine of theirs answers the fact. The verifier gets them as `owner_words` on the fact with the rule that they are strong evidence: it judges the fact like any other but never retires it against them; when the sources truly conflict with their words it asks them (mark `owner`), and their words alone are never a reason to ask. A mark that would retire such a fact (keep the other side of a pair, retire on a stale check) becomes a question for them ("You said "...". An agent reads B as the current one; do your words still hold?"), and so does `query` on a pair with such a fact (conflicts_with lets delivery drop one side); a mark that neither retires it nor marks it conflicting lands. No other agent path retires it without them: the curator's judge never supersedes it (its "supersedes" becomes a `supersedes? ... owner decides` line; the index carries a `words` column for this), and `tacit resolve` refuses to supersede, mark or clear it. A fact taken off kind user with no words of theirs found is a plain observation, guarded by nothing. `tacit resolve`, which agents can run, refuses to supersede, mark or clear a ruling or a fact with words of theirs: only the owner changes those, in tacit app or the review page.

**The audit.** `tacit rulings audit [--dry-run] [--strict] [--recheck] [--digests DIR] [--digests-only] [--sample N] [--json FILE]` reads every curated fact the old definition treated as a ruling (`source.kind: user` or `type: user_standard`) and every fact that carries evidence (their words included), and decides it, no model: written by them, kept; a quote that proves the rule, kept with `owner_quote` and `owner_quote_from` (and `endorsed` when the owner also kept it) and a ledger entry; their decision found, kept with `endorsed`; a short quote, `source.kind: observed` with `owner_words` and a words ledger entry; otherwise `source.kind: observed`, type unchanged, evidence fields cleared. It puts nothing to them: the report says "put to them: 0; pending: 0", and the marker lists no facts. A marker an older audit wrote with a pending list is carried forward, then rewritten without it: every fact on the list is a candidate again whatever its type, and a short quote it recorded (the quote and where) becomes the fact's `owner_words` with a words ledger entry (turn hash `pending-list`) when no other words of theirs are found, since it is the only record once their transcript is gone. An observed standard with their words becomes kind user. Only the `source` block changes (`fact.PatchSource`), so `updated` and the body stay. A real run writes the facts, the ledger and the marker through the curator's locked write (`curatorWrite`: lock, sync, plan on the fresh clone, refuse a file with uncommitted changes, lint, write, `MEMORY.md` without facts the clone does not track, lint again, one named commit as curator, files put back on any failure, a lost push race plans again); a dry run reads the clone as it is and never syncs. A quote (or words) the ledger holds stands without a new lookup; `--recheck` looks it up again. The ledger merges by union (`.gitattributes`, each union line checked on its own by `ensureAttributes`), like the decision log. A second run changes nothing. It never runs on an empty corpus: when none of their turns can be read, it refuses (fail closed).

**The curator.** The split and the rulings pass ask for `owner_quote`, their words exactly as the note gives them (at least six words), and say that an agent's reading is observed. The client keeps a `kind: user` entry only when a quote (the entry's, or a phrase of its text) is in the note it came from, proves the rule, and is theirs: a note the app added for them (their blockquoted lines; the app's template around them is not theirs), or a statement in their turns (the note's session first). The quote goes into the fact's text if the model left it out, and into the ledger. Anything else is written as observed (`not_owner_words` in the run's report). When their words cannot be read (no transcripts on this machine, a source that fails to load), the run curates no note: it fails and leaves them pending.

**The owner's notes that disown facts.** An owner note the app added whose own words say a fact is not theirs ("not owner wording", "non owner rulings", "not my rule", "interpretation of agents"; not when a negation of theirs comes right before the phrase: "these are my words, not an interpretation of agents") is not split into facts. It is about one fact, or the facts its finding marks: the facts their words name; else the one fact of a single finding (a stale check, a dead link); else, on a pair, the side their answer marked (keep A, retire B: B; neither, conflicting or both true: both); a note with no answer on a pair names no side. Each curator run, before the link step, sets those facts to `source.kind: observed` and clears their evidence, their words included (`curateDisowned`, the same locked write, commit `curator: N fact(s) the owner says are not their words ...`). The later of their words wins: a note over an older keep or This is mine, a keep or This is mine over an older note (the note's time is its adding commit's). A fact the owner wrote themself stays theirs.

**Rollout.** Install this client on every machine first: an older client decodes frontmatter strictly and drops every fact that carries `owner_quote`, `owner_quote_from`, `endorsed`, `owner_words` or `owner_words_from`. It changes nothing by itself (no marker, old definition). Then run `tacit rulings audit --dry-run`, review it, and run it for real; every client switches at its next sync.

**Import.** A memory its system files as the owner's (a Claude `feedback` memory, a Codex user preference or profile) is kind user only when one of its quoted phrases is a statement of theirs that proves the rule (the same checks, the memory's session first); otherwise observed. Without their words readable, nothing is imported.

## Derived facts

`tacit curate` runs a git pass after its inbox batches, and `tacit derive` runs it alone. No model is called. For each repo that has a live curated `projects/<repo>` scope (at least one non-inbox, non-superseded fact) and a checkout at `~/projects/<repo>` (its own `.git`, file or directory), the curator writes two facts under `derived/<repo>/`, as `curator`, with `source.kind: derived` and `derived_from: <12 characters of the commit it was read at>`:

- `<repo>-hot-spots` (type `hot_spot`): the 10 code files touched by the most commits in the last 400 code-touching, non-merge commits, each with its commit count, its last-touch date and up to 3 co-change partners (files in the same commit at least 3 times and in at least half of this file's commits). A file needs 3 commits to count. Commits that touch more than 30 code files are not counted. No fact is written when no file reaches 3 commits.
- `<repo>-module-map` (type `structure`): one line per directory with its file count, code file count, most common extensions, the number of window commits that touched code in it, and the date of its last change; plus the root files. The top-level directories are opened into subdirectories, code-rich ones first, until the map holds 30 lines. A directory is opened only if it is mostly code, most of that code is below it, and it has two or more subdirectories. No fact is written when the map has fewer than two lines.

Code is a fixed allowlist of extensions and build file names (`client/internal/derive/code.go`); data, logs, lockfiles, prose, vendored and generated paths are not counted. Blame age is not a fact of its own: line age in a young repo says little (memra is five weeks old, most repos here are under a year), and the actionable part, which module is dormant, is the last-change date on each module-map line.

Names are text chosen by whoever committed them, and a description is the line a hook prints into an agent's context. So a file or directory name is written into a fact only if it matches `[A-Za-z0-9._@+=,~-]` per component (components up to 100 characters, no spaces, quotes, colons, brackets or non-ASCII) and does not match the server's secret scan. Other names are left out and counted in the body ("N files ... are not shown"). README prose is not copied either.

Which commit. The branch the machine's config names for the repo, else the remote default branch of the checkout (`origin/HEAD`'s target, else `origin/main`, else `origin/master`), so that a feature branch that happens to be checked out never becomes a shared fact. With none of those (no remote, never fetched) the checkout's HEAD, and the body then says which branch ("no remote default branch found"). A branch name is written into a body only if it passes the same conservative character set and length bound as a path; otherwise the body says "branch name not shown", and an `origin/HEAD` pointing at such a name is not taken as the default. The body always names the ref, the commit and the commit's date ("read at commit b1bbd74f287f of 2026-10-05"), so a stale read shows.

The config is `~/.config/tacit/derive.yaml` (or `$TACIT_DERIVE_CONFIG`), written by `tacit derive --set-branch <repo>=<branch>` (empty branch removes the entry) and read by `tacit derive` and `tacit curate`:

```yaml
branches:
  sglang: dev
ordinary_names: [atlas, beacon]
```

`ordinary_names` lists repo names that are also plain words. gitev counts such a name as the repo a fact is about only when the fact's scope or `applies_to` names it, or its text mentions it three times or more (see Git evidence). A built-in set (`tools`, `tacit`, `docs`, `web`, `api`, `app`, `site`, `notes`) always applies; the list adds to it. `--set-branch` keeps it.

A configured branch is read at `origin/<branch>`, else at a local branch of that name, else the run falls back to the default and says the branch was not found. A file that does not parse (unknown key, a branch name that could be an option) stops the step. The case that made it: a fork whose `main` mirrors upstream and whose `dev` is the production tree (main plus the carried patches), so the useful facts are dev's. Set with `tacit derive --set-branch sglang=dev`.

Fresh reads. Before reading a repo, a real run of `tacit derive` or `tacit curate` (not `--dry-run`, not `--out`, not `curate --dry-run`, which use the network and move no ref) runs `git fetch --no-tags origin +refs/heads/<branch>:refs/remotes/origin/<branch>` in the checkout (`--no-fetch` skips it). It moves that one remote-tracking ref and nothing else: not the working tree, not a local branch, not HEAD, not FETCH_HEAD, no tags, no gc, no commit-graph. The timeout is 30 seconds: on the workstation at load 40 one branch with a few days of commits took 1.1 s (valkey-glide), 2.0 s (sglang dev), 2.6 s (memra) and 9.9 s (sglang main, the busiest), so 30 s is three times the worst and a dead link costs half a minute, not the three minutes a repo is otherwise allowed. A failed fetch leaves the ref as it was (git moves it only after the objects arrived), the read falls back to it, and the run report says "fetching origin/<branch> failed". After three failures in a row the other repos are not fetched (a dead network would cost every repo the timeout) and the run says so. A checkout without an `origin` is not fetched and not reported. Whether the fetch worked is not written into the fact, which is a function of the commit read; the commit date in the body is what shows a stale read.

The facts are a function of that commit: dates are the commit's, the host is the curator's, and nothing depends on the clock. The same commit gives the same bytes, a repo whose commit did not move is not recomputed or rewritten, and a moved commit rewrites both files. A derived name that a curated fact already uses, or that another repo's name slugs to, or a file already at the path that is not a generated fact, is skipped and reported on every run.

Who owns a repo's derived facts. The host that produced them (`source.host`). Another host does not rewrite or retire them unless run with `--take-over`, so a Mac with three checkouts cannot delete the workstation's 39 or flip the facts of a repo both have.

Retiring. When a repo loses its `projects/<repo>` scope or its checkout, the generated files under `derived/<repo>/` are removed (the one exception to supersede, never delete), by the host that produced them. Nothing is retired when no checkout can be found at all (an unmounted projects directory), on a partial run (`--repo`), or when a `projects/` or `derived/` fact does not parse (the scope may only look gone); unparsable facts are reported.

Writing. The facts are computed in memory; nothing touches the clone until the store lock is held. "Unchanged" is decided against what the server has (`origin/main`), not the working tree. Under the lock the step syncs, removes the generated facts a killed run left under `derived/` (and restores generated ones it changed) and puts `MEMORY.md` back to what is committed; a file there that is not a generated fact, committed or not, is never touched; writes what still differs, regenerates `MEMORY.md`, lints, and pushes once with `CommitPushOnceLocked`; a push that lost a race starts the locked part over. On any failure (cancelled context, a push error that is not a refusal, a linter that cannot run) the clone is put back exactly and any local commit dropped. A lint finding on a file this run wrote drops that repo. When the server refuses the push, the repos its lines name (`tacit: derived/<repo>/<file> looks like it contains a secret`) are dropped and reported with those lines, and the rest go in one commit again; a refusal that names no repo halves the set and pushes the halves. One bad repo costs one extra push, not one per repo, so the store lock is not held for minutes.

Numbers (window, changeset limit, thresholds, caps) and the evidence for each are in `client/internal/derive/analyze.go` and `eval/VALUE.md`.

## Results from git

`tacit curate` runs a results pass after the derived-facts pass, and `tacit results` runs it alone. No model is called. Git is often more correct than what an agent saved for a measured number, and a newer commit often replaces an older result that a saved fact still quotes. The pass reads the results committed to the repos that have a live `projects/<repo>` scope and a checkout (the same repos, the same branch and the same refs as the derived facts; it fetches nothing, `tacit derive` does), turns them into `result` facts that carry the commit, and flags the saved facts that quote a value a newer commit replaced.

What is read. Files touched by at least two of the repo's newest 6000 non-merge commits, of three kinds, each read in its newest version first and only then through up to 40 older versions:

- **Row logs** (`.jsonl`, `.csv`, `.tsv`): columns are classified by what they are. A metric is a numeric column whose name says it is a measured quantity (tok/s, throughput, latency, ttft, p50 to p99, accept, accuracy, f1, score, speedup, cost and the like; a counter such as `accept_n` is not). The setup is the string, small-integer and boolean columns that repeat (`cell`, `profile`, `arm`, `concurrency`). A time column (`ts`, `date`) orders the rows and a code column (`git`, `commit`) says what was measured. A row that its own `window_clean`, `valid` or `ok` column marks false, or its `error` column marks true, is not a result. A row log needs the row's own timestamp: rows without one are samples (per-request timings) and make no series. Rows of one setup are one run only when they share a full timestamp (a date alone is not one) and the same code; those become one point, their median, and the fact says how many rows it is. A column that counts runs is read as a count, and a file of per-item rows (a list of items, cases or samples) never makes a median: rows that share a run's timestamp but differ in what they say besides their numbers make no series. Runs are ordered by their time, and runs with the same time (a bare date) stay in the order of the file. Rows that each have a time of their own are one quantity measured again even when a column (an id, a note) is unique to each row; a per-request log with such a column is therefore read as a series.
- **Boards** (`.json`): every numeric leaf whose key path says it is a measured quantity; array elements are named by their `id`, `name`, `model` or similar field, and an object whose entries are all objects (three or more) or all numbers (two or more) under names that are not metrics is a table keyed by its entries (`scenarios.<name>.stages_ms.<stage>`). Not read: names that say a setting rather than a measurement (`timeout`, `deadline`, `budget`, `interval`, `window`, `expected`, `threshold`, `limit`, `target`, `lease`, a count or an id); the statistics that describe a number's uncertainty (`ci*`, `lower`, `upper`, `*_lower`, `*_upper`, `one_sided_*`, `delta*`, `stderr`, `std`, `p_value`); anything under per-item or per-slice records (`items`, `cases`, `samples`, `slices`, `per_task*`, `per_item*`, `per_slice*`) and `stages_ms`, which hold one item's score or a CI gate and not the result of a run; files named `*baseline*` or `*parity*`; and `analytics/`, `telemetry/` and vendored directories.
- **Tables** (`.md`): every table whose numeric columns carry a unit or a metric name; a row is its first text column (a repeated label drops the rows it names), a column is its header. A cell that is a range, an arrow or prose is not a number, and a cell whose unit disagrees with its header's is skipped.

A series is one measured quantity for one setup in one file. A setup (or a log row) that the file's newest version no longer holds is dropped, so a renamed column never leaves its last value standing as current. Its points are the values it held, each with the commit that wrote it (for a log row, the commit that first held that line; for a board or a table, the commit that changed the cell), the row's own timestamp and code reference where it has them, and the source line. A number written with seven or more decimals is shown with four significant digits and the raw text in brackets. Names, labels and setup values come from the repo and end up in a file a hook may read, so each must be one line of at most 60 characters with none of the characters that make a link, a code span, a quote or markup; a row that fails is left out. Every string from the repo is passed through `digest.RedactAll` (one call per repo) before anything is built from it: the file name, `applies_to`, description and body are made from the redacted strings, and only then stripped and clipped, so a clip never cuts a secret in two and a secret shaped like `password: x` is masked before it becomes part of a name. If redaction fails there is no fact.

A git read that fails is never a reason to retire a fact. A history read that errors, times out, returns a blob that is not the one asked for, or is cut short by a size budget marks the repo. With an error or a timeout the repo is reported failed: nothing is written and nothing is removed for it. With a budget cut the facts that were read are written and none is removed. Only a complete read may remove a fact whose series left the history.

What becomes a fact. Series are grouped by file and metric (a log), table (a document) or schema path (a board), and a group becomes one fact `derived/<repo>/<repo>-results-<file>-<group>-<hash>.md` with `source.kind: derived`, `created` and `updated` the newest commit date among its rows, and `derived_from` the commit that wrote the newest row (not the repo HEAD, so a repo whose results did not change gets a byte-identical fact and no commit). Only rows that recur (the series held two different values) or that a curated fact quotes are shown, at most 20 per fact, and at most 24 facts per repo: the repo's derived scope also holds the hot-spot and module-map facts and the prompt hook ranks it for one line, so many result files must not bury them. The cut keeps the groups a saved fact quotes, then the ones with more rows, then the newest.

The type says whether a hook may print the fact. Type `result` is a row log, a table or board group that a curated fact quotes, or one that a saved fact was retired in favour of (its `superseded_by` points at the result fact: accepting a flag retires the saved fact, and the replacement must not leave the hook with it). Type `result_ref` is every other group: `tacit search` and the MCP tool find it, the prompt hook does not print it. The description is made only from the file name, the metric (a name of at most four parts, else the unit), a count, a date and, when the row's label is a cell id, one row and its number: `<repo> <file>: <metric> for N setups, newest <date>`, then `; <label> <value> <unit>`. The row is the fact's first row, which is a row a curated fact quotes if there is one and otherwise the one whose value changed most recently; it is not chosen for the prompt, the hook prints the stored line. A cell id is one to three tokens of up to three alphanumeric parts joined by `-`, `_` or `.` with an optional `key=` prefix, each token holding a `=`, a digit or a separator, at least one digit in all, optionally followed by ` / column` for a table row (`cell=26b-spec-d1736 profile=balanced`, `frtrim27-mixed / tok/s`). Any other label stays in the body. No free text of the repo reaches the line a hook prints beyond that, the file name and the metric.

A row line gives the setup, the value with its unit, the basis, the commit that wrote it, the date, the code it measured (a log), the source line (`file:line`, or the JSON path), what it replaced and, for a log, the span of its last three values. Line numbers are those of the file at the commit the body names ("as the file stands at commit X", the newest commit that touched the file). The commit on a row is the one that first held that value, and the file may have been numbered differently then. The basis is what the file says: `median of N rows of one run (one timestamp, one code)`; `single run (the file says so)` only where the file has a run count of one; `N runs, how they are summarised is not stated`; otherwise `run count not stated` (a lone log row is `run count not stated (one row)`). A newer commit rewrites the same fact (the name depends on file and group only), so the store ends with the newer result and the store's own history keeps the older. A fact whose series left the repo's history is removed like a derived fact, unless a saved fact points at it with `superseded_by` or `conflicts_with`.

Which saved facts are flagged. A curated, non-superseded, non-derived fact (inbox notes are not delivered and are not checked) of a type that makes claims (a `history`, `past_mistake` or `code_change` fact records what happened and is never flagged) quotes a row when a number it states equals a value the row held, at the precision the fact wrote it, with at least three significant digits (a number of one or two digits is in every note); the unit written after the number is the row's unit; and the words that tell the row from the other rows of its group (its setup tokens) are in the fact: 60 percent of them, two at least (a row told from the others by one word is not matched); a ratio or score with no unit needs all of them. A whole number's trailing zeros do not count as digits (200, 480 and 1,000 are round figures), and a whole number cannot stand for a value that has decimals unless it has four digits. A number that sits in a bound is not a claim about what was measured: "must stay above 138.5 tok/s", "target 200", "a 1000 ms p95 bar", "at least 40" are skipped. All the numbers a fact states for a row are weighed together: if any of them is the current value ("went from 138.5 to 161.3", "161.3 now, was 138.5") the row is named by it and the fact is kept as it is. If it quotes only a value that was replaced, the fact is flagged when the difference to the current value is more than 1 percent and, for a log, outside the noise band of the new state (the replacing point and everything after it). Noise needs a sample to be called noise: under three points there is none, so 5 percent stands in for it (perf-ci's GPU cells move 2 to 5 percent between runs of the same code); with three or four points the band is the larger of 2 percent and half the observed range; from five points, the larger of 2 percent and three times the median absolute deviation. A flag also needs that the fact was not written before that value was recorded (a week of slack), and that the sentence around the number carries no date on or before the day it was replaced, since a fact that dates its number is a record and not a claim about now. A curator fact's dates are the day it was filed, not the day it was true, so a flag never says that a fact was wrong when saved.

A flag is a line in a review file the step owns whole, one per repo: `review/<date>-results-<repo>.md`, rewritten with the lines it already holds plus the new ones. `- result-superseded? [[<result fact>]] may replace [[<saved fact>]] - quotes ...`, with the quoted value, the commit that recorded it, the commit that replaced it and the value now. The file goes in the repo's own write, so a repo that failed or was cut gets no flag, and a repo the server refuses or the linter drops loses its review lines with it. The review page reads a line as a pair, A the saved fact and B the result fact, kind `result-superseded`, and the verifier is told to check that A names the same setup and quantity as B's row. B is generated and the next run rewrites it, so the page offers only the marks that leave B alone (retire A in favour of B, or keep both) and never one that patches B. A pair already in any review file is not raised again, whatever was answered. The step never retires a fact. A saved fact that is an owner ruling (`source.kind: user` or type `user_standard`) is put to the owner as `- RULING CHANGE? new [[<result fact>]] may supersede owner ruling [[<ruling>]]` and nothing else: the committer of a results file is usually an agent, so a commit is evidence of what was recorded, never a ruling.

Cost. A repo's read is cached by the commit it was read at, under `~/.cache/tacit/results` (or `$XDG_CACHE_HOME`), so a repo whose HEAD has not moved costs a cache read and one redaction call. Measured 2026-10-10 on the workstation at a load of 60 to 100, `nice -n 19`: every checked-out repo 34 s cold and 11 s warm, with identical output; one repo 2.4 to 2.8 s warm, against 34.5 s for `tacit derive --dry-run --out` over all repos.

Delivery is the derived facts' (see Delivery): the prompt hook's second query over `derived/<repo>`, at most one line, marked `(computed from git)`, only for type `result`, never SessionStart; `tacit search` and the MCP tool find both types. The host that produced a repo's result facts is the only one that rewrites or removes them (`--take-over` overrides). The write path is `tacit derive`'s: computed in memory, then under the store lock after a sync, written, linted, pushed once, with a refusal dropping only the repo it names.
## Staleness check

`tacit curate` runs it last, after the derived-facts step and the run's state, also when no inbox note is pending, and `tacit stale` runs it alone (`--dry-run` reads and prints, syncs and writes nothing). No model is called, and it never changes a fact: it writes findings. A fact git has overtaken is a question for the verifier or the owner, not a decision.

**Candidates.** Every curated fact that is not superseded, not retired, not under `derived/`, and has no unanswered stale finding. They are taken least recently checked first: each machine keeps a cursor in `~/.local/state/tacit/stale.json` (fact name, time of its last finished check), and a run reads git for at most `--budget` (45 minutes in `curate`); the facts it did not reach come first the next time. A fact whose read did not finish (a command timed out, a file list or a search was cut, the branch could not be read) flags nothing and is not marked checked; it is retried the next day (20 hours), then every 2nd, 4th and 7th day, so one that never finishes costs a seventh of a run, not all of it. `tacit stale --fact NAME` ignores the wait.

**Date.** A fact is current as of its effective date (`gitev.Builder.Effective`, the timeline's own dating): the date its text says it is from, else its source note's date, else `created`; moved forward by an `updated` day that differs from `created`, and by the day of its last store commit when the file was committed more than once. A curator fact filed in October from a note written in May is current as of May: the filing was a rewrite, not a check against git. Commits count from the end of that day; after a "still true" mark, from the instant of the mark.

**Rule.** gitev reads the fact's subject (see Git evidence) in the repos it names, each at the branch `derive` reads it at (`~/.config/tacit/derive.yaml`, else the remote default branch; HEAD only for a repo with no remote), not at whatever the checkout has out; the remote-tracking refs are the ones the derived-facts step has just fetched, and `tacit stale` by hand does not fetch. Of the fact's identifiers only specific ones are searched: a flag, or a name with an underscore, hyphen, scope, dot or digit in it, or capitals inside it (`gitev.Specific`); a plain word such as `suspended` never is. A fact is flagged when, at or after its date, something it names was deleted:

- a path it names is held by no repo read and a commit touched it (deleted or renamed): the newest commit that touched the path is read directly, so the others around it cannot hide it, or
- a commit removed or rewrote a line holding an identifier it names (a line the same commit adds back unchanged elsewhere only moved) and no repo read holds that identifier at HEAD any more (a rename leaves the old name nowhere). Only names that are gone are searched for in history, so the commit that removed one is among the few that touch it.

"After its date" is the committer date, the date git's `--since` filters on and the day a commit reached the repo (a rebased or cherry-picked commit written earlier counts from when it landed).

Not flagged: a commit that only touches a file the fact names, one that only adds lines holding an identifier, a rewritten line whose identifier still stands at HEAD (a reworded doc, a refactor, a changed value), and any term found in 26 or more files at HEAD (gitev drops it). So a hot file does not flag its facts and a deleted name does. The first design flagged every changed line holding a name; hand-checked it was almost never a stale fact, while deletions were (numbers in eval/VALUE.md), so a changed line that leaves its name standing is not a trigger.

A read that failed, ran out of time or was cut (a file list, a search, or the diff of a commit that removed a name: it is read with `-G` so only the files that hold a gone name are in it, and one past 600 KB is incomplete) flags nothing, whatever else it found: a file list that failed says nothing about a path (it is neither present nor absent, as for an identifier whose search failed), and a cut search can miss the commit that did it. The fact is skipped as incomplete.

**Once per commit set.** The finding's key is its newest triggering commit. The same commit never makes a second finding. A fact with a finding nobody has answered (no mark, or an unanswered question) is not flagged again, however many commits follow: the page and the verifier read git fresh. An answered finding no longer holds the fact back: a "still true" mark moves the fact's date to the mark, and a deletion after it, of a name or a file, is a new event that flags again; an agent's `fix` that waits for the owner does not hold the check back either, and the new finding carries the old fix.

**Cap.** A run writes at most 60 findings (`--max`, the verifier's default batch per run), strongest first: most deleting commits, then newest, then name. The rest are found again next run and the report says how many were held.

**Finding.** A line in `review/<date>.md` with a few indented lines for a person; the first line is what the page and the verifier read back:

```
- stale? [[name]] (scope) @abc1234 n=3 since=2026-10-01
  commits count from 2026-10-01 (text); 3 deleted something the fact names
  2026-10-09 abc1234 memra: engine: rename FOO to BAR - FOO (gone at HEAD)
```

`@sha` is the newest triggering commit, `n` how many commits deleted something the fact names, `since` the day commits started to count. The newest finding of a fact is its finding; older ones are history. Its id is a hash of the kind, the fact and the sha.

**Marks.** In `review/decisions.jsonl` like every other finding: `current` (still true), `retire` (outdated per git: the fact gets `retired: <date>` and `updated`; reopen restores both exactly), `fix` (an agent: true, but a detail changed, and what), `ask` (an agent's question for the owner), `reopen`. A `fix` is closed when the fact file is committed after the verdict (the owner or the curator applied it), or when the owner marks the finding; applied, it dates the fact. A finding whose fact is already retired or replaced takes no mark and does not need the owner. An agent may make only `current`, `retire`, `fix` and `ask`, and none on a finding the owner marked or reopened or on a fact the owner kept in a pair. The page shows a stale finding as one galley with the two owner marks, why git flagged it, and the same "What git says" timeline the pairs have, read for one fact (`gitev.Builder.BuildOne`).

**Rulings.** A ruling (`fact.IsRuling`, see Rulings) can be stale too. It is flagged like any fact, `tacit verify` never sends it to a model, and whatever an agent marks on it (`retire`, `fix` or `current`) is turned into a question for the owner and nothing is written into the file. Only the owner retires a ruling.

**Verifier source directories.** The store is required. `TACIT_VERIFY_ROOTS` adds read-only source directories, separated like `PATH`; each must exist or the verifier fails before calling a model. Claude auto-memory for `$TACIT_PROJECTS` (default `~/projects`) is included when present; its absence does not block a fresh install.

**Verifier.** `tacit verify` takes stale findings after the pair findings, in batches of their own, with the fact, the commits that triggered it and the one-fact timeline as input. Its marks are `keep` (still true, recorded as `current`), `retire`, `fix` (needs the corrected detail) and `owner` (a question). Evidence is required for all but `owner`, as for pairs, and free text is redacted before it is stored.

**Dry run and rollout.** `tacit curate --dry-run` does not run the scan (it can take most of an hour); `tacit stale --dry-run` does and prints what it would flag. The scan runs last in `curate`, after the run's state is saved, with every git command under `nice -n 19` and, where `ionice` exists, the idle I/O class (`gitev.Git.Low`: the children are wrapped, because a priority set on the calling process would reach one thread of it only), and the unit sets `Nice=19` and `IOSchedulingClass=idle` for the whole service. A binary from before `retired` rejects a fact that has it (the frontmatter decoder is strict): such a machine skips that fact, prints "did not parse" and fails `tacit lint` until it is upgraded, so install this binary on every machine before the first verdict retires a fact.

Numbers (what day one flags, how many of those are really stale, cost per fact) are in `eval/VALUE.md`.

## Link repair

`tacit curate` runs it after the derived-facts and results steps (once, also when no inbox note is pending; `curate --dry-run` runs its dry run), and `tacit links` runs it alone (`--dry-run` reads the clone as it is, prints each repair it would make, syncs and writes nothing). No model is called. A link that names no fact (lint L6) is a link nobody can follow; the curator settles each one by rule, and a fact it cannot settle by rule is the owner's.

**Dead link.** Only a link counts: a `[[name]]` in a fenced code block (``` or ~~~), an indented code block (four spaces or a tab after a blank line, outside a list) or an inline code span (a TOML `[[table]]` header, an example) is code, for lint L6 and for this step alike, and is never read or touched. A `[[target]]` in the rest of the body of a curated fact is dead when its target names no fact in the store (inbox notes count as facts, as in L6), or names only curated facts that something replaced (`superseded_by` set) and a live successor is clear. A link to a live fact, to a retired fact with no successor, to a fact whose chain loops or dead-ends, or to a name only an inbox note holds, resolves for lint and is left as it is. Inbox notes are never edited, and a generated `derived/` fact with a dead link is reported on stderr and left to its generator, which rewrites it.

**Clear match.** A dead link is rewritten to a fact name only when exactly one live curated fact answers to it, by one of these, in this order:

1. The target is the name of one superseded curated fact: follow `superseded_by` (at most 16 hops) to the live fact at the end of the chain.
2. The target spelled as a fact name is exactly one live curated fact. Spelled as a fact name: lower case, a trailing `.md` dropped, every run of `_`, `.`, `-` or spaces one hyphen (`[[Gpu_Notes]]` and `[[gpu-notes.md]]` are `gpu-notes`). If that name is held by a superseded fact, rule 1 follows from there.

Not a match, by decision: a repo name. `[[codex-desktop-linux]]` names a checkout, and the facts about it (its module map, its hot spots, the project facts) answer different questions; pointing the sentence at one of them changes what it refers to, and "reads naturally" is not something a rule can test. A repo name is plain text like any other name nobody answers to. Also not a match: a fact merely similar in name or description, a name that two live facts answer to (ambiguous), and a rewrite that would make a fact link to itself.

**What gets written.** A rewritten link becomes `[[<fact>]]` and keeps its label, the text after the first `|` (`[[a|label]]`, `[[a#section|label]]`); a `#section` is dropped (the section belonged to the old fact). Every other dead link is unwrapped to plain text, its label if it has one, else its target: `[[keys]]` becomes `keys`, `[[a|the label]]` and `[[a#section|the label]]` become `the label`, `[[a#section]]` becomes `a`. Nothing else in the file changes: the frontmatter and every byte of the body outside the links stay as they were (the file is edited in place, not re-encoded, and replaced by a rename so a killed run leaves it whole), `updated` is not touched, and `MEMORY.md` is regenerated from the tree as the commit will hold it (a fact the clone does not track, or has only staged, is not in it). A repaired fact is not "edited" for the staleness check: the commit subject starts with `curator: links:`, and `gitev` leaves such a commit out of a fact's store history only when the commit's change to that file is a repair (`links.IsRepair`: the same file with links replaced by a link to another target with the old label and no section, or by the plain text this step writes, and nothing else), so a sentence under that subject still counts as an edit. Without the skip, a fact repaired today would hide every deletion between its own date and today from the check.

**Rulings.** A ruling (`fact.IsRuling`, see Rulings) is not edited. For each ruling and each dead target the curator appends one line to `review/<date>.md` under a `## link check` heading:

```
- LINK? [[<ruling>]] (<scope>) links to [[<target>]], and <why>; this is an owner ruling, so the curator left it; it would write <plain text | [[fact]]>
```

Once per fact and target: a target already named by a `LINK?` line for that fact in any review file is not raised again, whatever the owner did about it, and a second occurrence of the target in the same fact does not make a second line. The line stays until the owner edits the ruling; lint L6 stays red for that fact meanwhile, by design. The review page does not list `LINK?` lines (they are not pairs); `tacit app` lists them in Needs you (see App).

**Write path.** The same as the other steps: under the store lock the step syncs, plans on the fresh clone (a repair is a function of the files, so a lost race recomputes instead of replaying), writes, regenerates `MEMORY.md`, lints, and pushes once as `curator`, committing only the files it names (`CommitPushNamedOnceLocked`: a change someone staged in the clone does not ride along); a push that lost a race starts the locked part over (up to three more times). The lint gate looks at findings that are new after the write: one the store already had (a fact with its own L7 that also holds a dead link) does not stop the repair; a new finding on a file the step wrote drops that file for this run and says so; a new finding anywhere else, a linter that cannot run, a refused push, a cancelled context or any other failure stops the run. On a stop every file the run touched goes back to the bytes it had when the run began (not to HEAD), and the local commit is dropped. What is left alone and reported as not done: a tracked fact file with changes in the clone that are not exactly what this step would write from its committed version, and a fact file the clone does not track (a curate batch killed before its push, a fact written by hand): never planned, written, committed or removed, and a link to such a fact is left as it is. What a killed run leaves is committed by the next one only when it is provably the step's own: a fact file whose bytes equal what the step writes now from the committed version of that file (never a ruling or a `derived/` fact), and a review file whose only uncommitted lines are this step's `LINK?` blocks. A hand edit to a link is not that, even when it touches only the link. Another writer's uncommitted lines in today's review file are never committed with ours; the owner lines wait for a later run. The report counts and names in the past tense only what reached the server; what was skipped, dropped or lost to a failure is "not done".

**Idempotent.** A second run finds no dead link in a curated fact that is not a ruling and every ruling line already raised, so it writes and pushes nothing. One exception by construction: a link nested in a link (`[[[[x]]]]`) leaves a new link when the inner one is unwrapped, and the next run settles that.

## App

`tacit app` is the owner's own window onto the store: what waits on them, every fact, and their edits. Code: `client/cmd/tacit/owner.go` (the operations), `app.go` (the methods the page calls), `app_desktop.go` (the window), `reviewui/app.html`, `desk.js`, `desk.css` (the page; design in `reviewui/DESIGN.md`, "The app").

**Two ways in, one code path.** The desktop window (Wails v2, the system webview) binds the exported methods of `App`; the page calls them through the webview bridge, so no port is open and no token exists. `tacit app --browser` serves the same page on a loopback port (127.0.0.1:7450) and answers `POST /api/call/<Method>` with the page's token, the review page's model. Both run the review page's own code (`reviewServer`): its items, marks, timeline and write path. The window is in a separate build (`-tags desktop,production,webkit2_41` on Linux, `-tags desktop,production` on macOS); the default `tacit` the hooks run stays pure Go, since the window's GTK and WebKit libraries cost every process start about 30 ms.

**Plain words.** The page speaks the owner's words, not the store's: fact, note (inbox), your rule (a ruling), retire, who it reaches (the scope, said as "in memra", "on workstation"), what agents read (the description), Details (name, file, frontmatter). Five places: Needs you, Your rules, What agents believe you prefer, All facts, Inbox (keys 1 to 5). Design: `reviewui/DESIGN.md`.

**Needs you** shows everything waiting on the owner one finding at a time, with "N left" as its only count: the review findings (pairs, `result-superseded?`, `RULING CHANGE?`, `stale?`, and the agents' questions on them, with the review page's marks), and one item per `LINK?` line. Each kind is asked as a fixed plain question with choices named by what they keep (Keep the newer, Keep the older, Both are true, Mark as conflicting; Use the number from git; Keep your rule; Still true, Outdated, retire it), each a mark the review page already had, and Skip for now, which saves nothing. Every pair also takes Neither is true (`wrong`): through the owner's write path (lock, sync, lint gate, one named `owner: neither is true: retire <a> and <b>` commit) both facts get `retired: <day>`, and one decision records both as they were (`before`), so reopen puts both back byte for byte. The owner may answer it on their own rulings; an agent never sends it, nor a note. Any finding takes a note in their words: sent with an answer it is the decision's `comment`; alone it is a `note` record that leaves the finding open, is shown on it, and is not a mark (the verifier still takes the finding). Either way the note is redacted with `digest.RedactAll` (fail closed: no redaction, nothing saved) and also written in the same commit as their inbox note (`inbox/human@<host>/owner-note-...md`, `source.kind: user`, quoting them with the day and linking the finding's facts by name), so the curator reads it like any remark of theirs. An open finding's notes reach the verifier as `OwnerNote`, which outranks every source: a verdict that would retire a fact of such a finding becomes a question for them. The two facts are named older and newer by the day each speaks for (the newest date in its text not after the day it was written, else that day); the older card is drawn left and the arrow keys follow the screen. An agent's question shows as its suggestion and reason, with its A and B named as the facts, never as a headline. What git shows leads with `Timeline.Summary` (Git evidence) and folds the dated events; a stale check also says what its finding line records as deleted, where and when. Kind, scope, find and past answers sit behind one Filter control. A `LINK?` item is open while the link planner still finds that dead target in that ruling (the line itself stays in the review file); it offers Apply the fix, which writes into the ruling exactly what the curator would have written for that one link and nothing else, and Edit the rule. A ruling that was retired or replaced closes its items.

**Your rules, What agents believe you prefer, All facts and Inbox** list every fact of the clone at its HEAD: Your rules is All facts with rulings only (`fact.IsRuling`), each with their words under it ("In your words: ..." for a quote; "You said this is yours" for an endorsement; "You wrote this"); What agents believe you prefer is the curated `user_standard` facts that are not rulings and every fact that holds words of theirs (Their words, shown as "Your words in it: ..."), less those the owner said are not theirs, said as what agents wrote down, not their words, each with This is mine (key m), Not mine (key x) and Retire; it is a place to browse, and nothing in it waits for them or reaches Needs you. Inbox holds the inbox notes. "Your rule" appears on a card, a tag, a hint or a question only for a ruling. Each opens on its search field; the filters (scope, repo (the project or derived scope, or `applies_to.repos`), type, source kind, status (live, retired, replaced, any), curated or with inbox notes) fold behind one Filter control. Free text uses the full-text index of the clone at its HEAD (`search.Index.Rank`: every scope, every term as a prefix; the view's filters are applied before the fallback, so all terms are required only while a fact the view shows has them all, and otherwise any one is enough; the query pages past its first page until it has as many rows the view keeps as it asked for, so a filter that drops most of the top hits never leaves the list short), after the facts whose name holds the query as typed. A fact opens with its description and body (with its `[[links]]`: live, retired, replaced, inbox note, or no such fact), one sentence of where it applies and its dates, and its actions; Details folds every frontmatter field, the curated facts that link to it, the store's git history of its file (author, time, subject; a commit whose subject starts `owner: ` or an owner's review mark reads "you") and What git shows (`gitev.Builder.BuildOne`, cached like a finding's timeline, read when Details opens).

**Owner writes.** Edit (description, body, scope, type, `applies_to`), Retire, Restore, Undo last edit, New ruling, This is mine, Not mine, Apply a link fix. Each runs `ownerWrite`: under the store lock, sync, plan on the fresh clone, lint, write the files, regenerate `MEMORY.md`, lint again, and push once as `curator` with `CommitPushNamedOnceLocked`, which commits only the files the write names (the fact, the old path of a move, `MEMORY.md`, `.gitattributes`), so anything else staged in the clone (a killed run, a hand `git add`) never rides along under the owner's name; a push that lost a race syncs and plans again (up to four times). A lint finding the store did not have before (keyed by rule, file name and message, so a fact's own old finding, such as a ruling's dead link, does not block it and a move does not make it new) refuses the write: the files go back to HEAD, the index cached for that HEAD is dropped, and the findings return to the form, which keeps the draft. A refusal by the server or a failed commit also keeps the draft. A fact file with uncommitted changes in the clone is not written; other files' uncommitted changes stay out of the commit (above).

**Stale forms.** A draft is kept by the fact's name (so a scope move made elsewhere does not lose it) and carries the hash of the file it was started on (`rev`) and that version's text, for as long as it lives, also across a refusal, a switch to another fact and a sync; the page never gives it the rev of a newer version by itself. An edit whose rev is not the file's (or has none) saves nothing and returns `changed`; the page then shows the version in the store now beside the draft (the lines the draft lacks marked, and the last change's author, time and subject) and offers two choices, focused on the first, and nothing is saved until the owner makes one (Esc returns to the choice and keeps the draft): Keep my draft (the draft takes the new rev and Save comes back; the store's version stays beside the form, folded on request, until the draft is saved; saving replaces it, and it stays in history) or Take the new version (the draft is dropped). What is marked in the store's version is what changed there since the draft was started, so the owner's own edits are not marked. A draft over a fact that changed while it was set aside opens the same way. Inbox notes are read-only and generated `derived/` facts are not edited or retired (their generator rewrites them).

- Edit re-encodes the frontmatter (`fact.Encode`), sets `updated` to the day, and keeps every other field. A scope change moves the file to the new scope's directory in the same commit and names the old path in the commit body (`Tacit-Moved-From: <path>`); this is a rename, not a delete, and the history follows it.
- Retire sets `retired: <day>` and `updated`, through `PatchRelations`, so only those lines change; the fact stays in the store and leaves the index, the hooks and search at once, like a staleness retirement. Restore clears `retired`. The owner may retire their own rulings; agents still may not (their guards are unchanged).
- Undo last edit is allowed when the newest commit on the fact's file (following a move) is one of the owner's `owner: ` commits and was not the one that created it; it writes the file as it stood before that commit (at its old path for a move) as a new commit, `owner: undo ...`, so history keeps both, and a second undo redoes. A ruling written in the app is retired, not undone.
- This is mine appends their decision `{"id": <mineID(name)>, "action": "mine", "a": <name>}` to `review/decisions.jsonl`, sets `source.kind: user` and `source.endorsed` to its id (`PatchSource`), in one commit `owner: this is mine: <name>`. Not mine appends `{"action": "not-mine"}` (`owner: not mine: <name>`): the fact leaves What agents believe you prefer and words of theirs it holds no longer guard it; the file is unchanged. While their Not mine stands, the fact's page says so, still shows their recorded words, and offers Undo Not mine (key x), which reopens the decision. An edit of theirs that takes the `owner_words` phrase out of the text drops `owner_words`. An edit of a ruling that rests on a quote and takes the quoted phrase out of the text records the same decision and rests the ruling on it: the words are their edit now. Undo of either appends a `reopen` of that decision (and undoing the undo records it again), so the audit agrees with the file.
- New ruling writes `<scope>/<name>.md` with `type: user_standard`, `source.kind: user`, `source.harness: human`, the machine's host, `created` the day, `applies_to.repos` the repo of a `projects/<repo>` scope, and the owner's text as the body, verbatim. The description is their first sentence unless the owner writes one; the name is a slug of it unless the owner edits it. A name any fact or inbox note holds is refused, except the inbox note the ruling is promoted from, whose name the ruling records as `origin`. The form asks which repo the rule is about first and lists scopes narrowest first (the repo, the machine, user, system), and says that agents tend to widen the owner's remarks when user or system is chosen. Promoting an inbox note opens this form filled from the note and changes nothing in the inbox; the curator may still read that note later, and a duplicate it makes is put to the owner as a pair.

Every commit subject starts `owner: ` (`owner: edit <name> (<fields>)`, `owner: retire <name>`, `owner: restore <name>`, `owner: undo ...`, `owner: new ruling <name> (<scope>)`, `owner: link in <ruling>: ...`) and its body says the owner made it in tacit app; the commit author is `curator`, the writer the server lets touch curated facts. These commits count as edits for the staleness check (they date the fact). The owner's text is not redacted: it is theirs, and the server's secret scan still refuses a push that holds one.

**Controls.** Every button draws one icon from one inline SVG family (20 px grid, one stroke weight, round joins) before its label and its key. No native popup opens in the window: each filter and the edit form's Type keep a hidden `<select>` as their model and are drawn as a button and a list the page renders (arrow keys, Home, End, Page keys, type-ahead, Enter or Space to choose, Esc to close). Free-text fields carry no `<datalist>`, and the two search fields are plain text fields (no toolkit clear button; Esc clears and leaves one). **Undo from a slip** is bound to the fact the slip was shown for, and asks the store whether undo is possible for it before it runs. **Concurrency:** the queue reads the review items under the server's mutex, since the window runs each call on its own goroutine.

`tacit install app` (from the desktop build) writes `~/.local/share/applications/tacit.desktop`, running `<that binary> app` (with `TACIT_STORE` when it is set), and the icon `~/.local/share/icons/hicolor/scalable/apps/tacit.svg`. It runs nothing. On macOS it writes `~/Applications/tacit.app` instead (see Install).

## Models

The client calls models through the configured runner: Claude, Codex, Hermes, Grok, pi, Muse or agy. `runner` selects the default CLI and `runners` overrides each role. Claude remains the default, with the aliases below; other runners use their own configured model when no model override is set. See [runner configuration and boundaries](docs/portable.md#model-runners). Each step has an environment override, which a job takes from its env file (`EnvironmentFile`, `--env-file`):

| Step | Default | Override |
|---|---|---|
| curator split and rulings pass (`tacit curate`) | `opus` | `TACIT_CURATE_MODEL` |
| curator contradiction judge | `haiku` | `TACIT_JUDGE_MODEL` |
| dreamer (`tacit dream`) | `haiku` | `TACIT_DREAM_MODEL` |
| verifier (`tacit verify`) | `opus` | `TACIT_VERIFY_MODEL` |

A `--model` flag, where a command has one, wins over the variable. On a provider that needs full model ids (a Bedrock inference profile, for example), set the variables to those ids.

## Install

`tacit install <target>` writes files and prints the commands that load them; it never starts a job. Every target is idempotent (a rerun replaces tacit's own entries and nothing else).

| Target | Linux | macOS |
|---|---|---|
| `claude`, `codex` | SessionStart and UserPromptSubmit hooks in `~/.claude/settings.json`, `~/.codex/hooks.json` | same |
| `follow` | `~/.config/systemd/user/tacit-follow.service` | `~/Library/LaunchAgents/ai.tacit.follow.plist` |
| `dream [--env-file F]` | `tacit-dream.service` (`EnvironmentFile=F`, default `~/.config/tacit/env`) and `tacit-dream.timer` | `~/Library/LaunchAgents/ai.tacit.dream.plist` running `tacit dream --env-file F` (default `~/.config/tacit/env`) |
| `app` (desktop build) | `tacit.desktop` and the SVG icon | `~/Applications/tacit.app` |

**launchd.** launchd has no `EnvironmentFile` and no `RestartPreventExitStatus`, so the two differences are carried by the binary, not the job file. The follower's agent runs `tacit follow --launchd`, `RunAtLoad`, `KeepAlive {SuccessfulExit: false, Crashed: true}` (restart after any failing exit or crash, as `Restart=always`), `ThrottleInterval` 5 (`RestartSec=5`); under `--launchd` the config exit 78 becomes exit 0, which KeepAlive does not restart, after the reason is logged. The follower writes its own log (`--log ~/Library/Logs/tacit/follow.log`): each line stamped with the local time, and a line that would take the file past 1 MiB first moves it to `follow.log.1` (replacing the older one), so the log never holds more than about 2 MiB; launchd's own `StandardErrorPath` is `follow.err.log`, which gets only start-up errors and panics. The dreamer's agent runs `tacit dream --env-file F` every 14400 s (`StartInterval`, not at load), and `--env-file` loads the file's `KEY=VALUE` lines (optional `export`, `#` comments, one pair of quotes removed) into the process before any model job; a missing file or a malformed line fails the run (exit 2) and no value is ever printed. Both agents: `ProcessType Background`, `LowPriorityIO`, `Nice` 10 (follower) or 19 (dreamer), stdout and stderr to `~/Library/Logs/tacit/` (the directory is created by install, since launchd does not), and `EnvironmentVariables` with `TACIT_STORE` when set at install time and a `PATH` of the binary's directory, `~/.local/bin`, the directories where `git`, `scrump` and the configured runners were found at install time, `~/.cargo/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and the system directories (launchd's own PATH lacks all of the first). Load with `launchctl bootout gui/$(id -u)/<label>; launchctl bootstrap gui/$(id -u) <plist>`. The curator and the verifier have no macOS target: they run on the curator's machine.

**The app bundle.** `tacit.app/Contents/` holds `Info.plist` (`CFBundleIdentifier ai.tacit.app`, `CFBundleExecutable tacit-app`, `CFBundleIconFile tacit`, `LSEnvironment` with the same `PATH` and `TACIT_STORE`, since Finder starts apps with launchd's PATH), `MacOS/tacit-app` (a copy of the running binary: macOS reads a bundle's Info.plist and icon only for an executable inside it; skipped when install runs from that copy), and `Resources/tacit.icns` (embedded in the desktop build from `client/cmd/tacit/macos/tacit.icns`, made by `scripts/make-icns.sh` from `reviewui/icon.svg`). The bundle is signed ad hoc with `codesign --force --sign -` when codesign exists. Finder starts the executable with no arguments (or `-psn_...`): run from inside a `.app` bundle, `tacit` then opens the window instead of printing usage.

**Read-only clone.** `tacit clone --read-only [--as <harness>] <url>` clones with `--config credential.helper=` (so no inherited helper answers, also during the clone itself), sets `tacit.readonly=true` and points `remote.origin.pushurl` at `read-only://this-clone-never-pushes`, a URL git has no transport for, so even a hand-typed `git push` in the clone fails locally and sends nothing. `Store.ReadOnly` reads `tacit.readonly`. With `--as` (normally `reader`, see Public path) the clone also gets `credential.<server>.helper` = `tacit credential <harness>` and `tacit.as=<harness>`: every fetch signs with that key, the follower signs the feed with it (`Store.ReadAs`), and `tacit authcheck` uses the clone's origin; the key must exist here before the clone starts (exit 2 otherwise). What it blocks, each before any work (no sync, model call, cursor move, file write or commit): the page writes (`applyOps` and `ownerWrite`: every mark, note, edit, retire, restore, undo, new rule, This is mine, Not mine, link fix); `tacit dream`; `tacit import`; and the curator's commands `curate`, `verify`, `stale`, `links`, `derive`, `results`, `resolve`, `rulings audit` and `review apply` (`refuseWriter`, exit 2). Their `--dry-run` and `--out` modes write nothing to the store and still run. `commitPush` also returns `ErrReadOnly` before it stages anything, and a review mark that meets it puts back every file it wrote, as a second line of defence. `tacit install dream` refuses a read-only clone. `addFact` (`tacit add`, the MCP tool) does not refuse: it writes to this machine's local overlay instead (Local overlay). Sync, the follower, hooks, search and the pages' views work as on any clone.

**Writer keys and view only.** The same up-front check (`writerCheck`) also asks, for a clone of the server (an `http` or `https` origin; a path remote needs no key), that this machine holds the key of the writer the command pushes as: `dreamer@<host>` for `tacit dream`, `curator@<host>` for the curator's commands. A machine without the curator key (a Mac set up by `scripts/mac-setup.sh`, by decision: it is never a curator) starts `tacit app` and `tacit review` view only: `Meta`, `Queue` and `/api/items` carry `view_only` ("View only on this machine. Edit from the curator's machine."), no finding offers a mark (`allowed` is empty), a fact offers no edit, retire, restore, undo, This is mine or Not mine, the page hides New rule, Make it my rule and the note box and shows that one line, and `writeRefusal` refuses every page write before it writes (label mode, which writes only its own label file outside the store, is unaffected). A read-only clone is turned into a writer clone by removing it and cloning with a key (`scripts/mac-setup.sh` does this when nothing in it is uncommitted).

**Mac setup.** `scripts/mac-setup.sh` is the whole first run on a Mac and every rerun (README "Mac"). It takes the server as a parameter (`--server` or `$TACIT_SERVER`, required: there is no built-in address; with `--read-only` it is the public path, such as `https://tacit.example.ts.net`) and, optionally, the ssh target the printed enroll line runs on (`--enroll-ssh` or `$TACIT_ENROLL_SSH`; without it the script prints the bare `tacit_server rpc` line to run on the server); it checks the server with `/healthz` (200 on the tailnet; 401, a key asked, is the public path's answer, accepted only with `--read-only`); it waits for enrollment with `tacit authcheck <harness> --url <server>`, which asks for receive-pack's refs with the writer's token (what `git push` asks first; for `reader`, upload-pack's refs, what `git fetch` asks first) and sends nothing, and clones after the keys are taken. `--read-only` creates only `reader@<host>`, clones with `tacit clone --read-only --as reader`, installs the hooks (claude, codex when `~/.codex` exists), the follower and the app (view only), builds scrump like writer mode (the agents' notes are redacted into the overlay), never installs the dreamer, and replaces an older read-only clone (another origin, or no `tacit.as`) when it holds no changes. Exit 0: the server takes the writer. Exit 1: wait (401 `unknown_key`, not enrolled yet; the server unreachable; 5xx). Exit 1 also for 429 (the public path holding off an address after failed requests) and for the public path's one 401 body. Exit 3: waiting cannot help (401 `host_mismatch`, `bad_signature`, `expired`, `unknown_harness`; 403; no key here). The script prints the answer on every try and stops at once on exit 3. scrump is built with `cargo install --rev` pinned to the commit that added the text profile. `--dry-run` executes only checks and prints each change; `client/cmd/tacit/macsetup_test.go` runs it on Linux against stubs of the macOS tools and asserts that HOME stays empty and launchctl, go builds and cargo never run.

## Public path

The server binds the tailnet address (`TACIT_PORT`, 7447) and, when `TACIT_PUBLIC_PORT` is set (7448 in the unit), a second listener on 127.0.0.1 only. Tailscale Funnel on the server host proxies public port 443 to that listener (`server/deploy/funnel.sh <host> on|off|status`); nothing else off the host can reach it. It exists for a machine that cannot join the tailnet (decision 2026-10-11: read only, the harnesses there share notes locally, no dreamer). Funnel is allowed per host:port, not per mount, so `funnel.sh on` reads the node's `tailscale serve status --json` and refuses unless 443 serves nothing yet or exactly `/` -> `http://127.0.0.1:7448` (`server/deploy/funnel_guard.py`: no other Web handler on `<host>:443`, no `TCPForward` or `TerminateTLS` on 443, no foreground serve session there).

**Telling Funnel requests apart.** By the listener: a request on the public listener is public (`TacitServer.PublicRouter` marks it), and Funnel only proxies to a local address, which is that listener. tailscaled deletes `Tailscale-Funnel-Request` and the `Tailscale-User-*` identity headers from what the client sent, sets `Tailscale-Funnel-Request: ?1` on every request that came in through Funnel (`addTailscaleIdentityHeaders` in tailscale's `ipn/ipnlocal/serve.go`), and overwrites `X-Forwarded-For` with the Funnel client's address (`addProxyForwardedHeaders`). So a request with `Tailscale-Funnel-Request` on the tailnet listener is a Funnel pointed at the wrong port or a spoof, and gets 403 at once: it is never taken for the node itself (whose own tailnet address is a WhoIs hit) and never reaches the public path's counters with a caller-chosen `X-Forwarded-For`.

**Rules on the public path.** Every route needs a `reader@<host>` key token (`Authorization: Basic <keyid>:<token>`): `/healthz`, `/journal`, `/events`, info/refs, upload-pack, receive-pack and unknown routes alike answer 401 before the route runs and before any body is read, and the connection is closed. Any other key (a writer's, the dreamer's, the curator's) is refused there: a private key copied off a harness machine must not become an internet-wide read credential. There is no tailnet node, so the key's host is not compared with one; the signature names the key. Every failure (no token, malformed, unknown key id, not a reader, expired, bad signature, replay) has the same body, `unauthorized: the public path needs a reader key token`, so an unauthenticated caller learns nothing about which key ids exist; the reason goes to the server log only. Unknown key ids cost no git: `Keys.public_key` first looks in the cached set of ids under `keys/` on main (one `git ls-tree` per 30 s, the positive key cache's TTL, dropped by every enrollment and every push that moves a ref). Nonces are claimed under one constant peer for the whole public path, so git's reuse of one token across a command survives a client whose address changes mid-command; a token first used on the tailnet listener is a replay here. A request whose token verifies is always served. A source (`X-Forwarded-For`) that has failed 60 times this minute gets 429 instead of 401 (a legitimate client fails once per git command, since git asks without credentials first); the counters live in their own table of at most 4096 sources, and a new failing source past that is answered 429. Every push is refused (403, "the public path is read-only"), on the advertisement and on the pack, before git runs; enabling pushes there would be a later decision of the owner. A feed stream on the public path ends after 300 s (the follower's own verification interval) with one `event: reconnect` frame; the follower reconnects at once with a fresh token and `Last-Event-ID` (a stream asked to end sooner than one reconnect delay is backed off like a failure), so a revoked reader key stops receiving journal rows within that time. The tailnet listener is otherwise unchanged: reads need a tailnet peer and no key, pushes a writer key.

**Reader keys.** `reader@<host>` is a key that only reads: enrolled like any key (`TacitServer.Auth.Keys.enroll`), it fetches and follows the feed on either path, and every push it makes is refused (403, "reader keys cannot push") on every path. It is the only key the public path takes. No fact is written as `reader` (`agentHarness` excludes it). `tacit authcheck reader` asks upload-pack's refs with the token; the public path's one 401 body means "not taken yet" there (exit 1, wait), since it cannot say whether the key is not enrolled yet or the clock is off.

## Local overlay

On a read-only clone, `addFact` (`tacit add`, the MCP `tacit_add`, the Hermes provider) writes to this machine's overlay, `$TACIT_LOCAL` or `~/.local/share/tacit/local/<harness>@<host>/<name>.md` (`client/internal/overlay`), in the store's fact format: the same redaction with scrump (fail closed: no scrump, nothing written anywhere), the same normalization, harness and host in `source`. A fact whose description and body any overlay file already holds is not written again, whichever harness wrote it; a name taken by another fact gets a short suffix. The overlay is a plain directory outside the clone and never a git repository; an overlay directory inside the clone, also through a symlink and before it exists (the nearest existing ancestor is resolved), is refused (`ErrInside`) and never indexed, so no commit or push can carry it.

Search reads it with the store: the index is keyed by the store's HEAD and a stamp of the overlay's files (`index-v5-<sha>-l<stamp>.db`), so a new note is found at once. Overlay facts carry the path `local/<harness>@<host>/<name>.md`, are never inbox facts, never rulings and never their words whatever kind their writer gave them, and are marked `(this machine)` in hook blocks and `tacit_search`. `tacit fact` and `tacit_fact` fall back to the overlay. They reach only the harnesses on this machine; they are not reviewed and never reach the store.

## Delivery

Two hook points, both reading the local index of the local clone, both failing open:

- SessionStart: after a bounded sync (skipped while a healthy follower has just confirmed the clone current, see Change feed), at most 10 facts for the session's repo and host (query: the repo and host names), as one line each. Derived facts are never in this block.
- UserPromptSubmit: at most 3 curated facts above a score floor, with the prompt text as the query, each fact once per session; nothing for a harness-injected turn or a prompt under two searchable terms. Then, from a second query over the repo's `derived/<repo>` scope only, at most one derived fact, if it clears its own floor (12, against 15 for curated facts). The curated query is the same one that ran before derived facts existed, so a derived fact never displaces a curated one and a repo with a thousand curated facts cannot crowd it out of its own ranking.

This machine's local notes (Local overlay) are delivered with the curated facts and marked `(this machine)`; SessionStart takes at most 3 of them (the prompt hook's count). Inbox facts are not delivered by hooks (unreviewed); `tacit search --inbox` and the MCP tool can include them. `tacit search` and the MCP `tacit_search` also search the repo's `derived/<repo>` scope. A derived line in a hook block is marked `(computed from git)`. Measured basis: eval/VALUE.md.

## Change feed

`GET /events` streams the journal as server-sent events. Over the tailnet reading needs no key; over the public path it needs a key token (Public path). The stream is "notify, don't carry": an event says the head moved; the content is fetched with git.

```
: connected head=<seq>                  first line of every stream: where the journal ends
id: <seq>
event: head_moved
data: {"seq":<seq>,"ref":...,"old":...,"new":...,"writer":...,"ts":...}

: keepalive                             every 20 s
```

The server replays every journal row with `seq` above the client's `Last-Event-ID` header (or `?since=`), then streams live rows. A client that was away loses nothing.

`tacit follow` is the client side. It holds the stream and, for each burst of `head_moved` events (1 s of quiet, at most 5 s), does what `tacit sync` does: fetch, fast-forward, reindex. The fetch runs without the store lock and lands in a private ref (`refs/tacit/follow/main`, fetched with `--refmap=` so git does not also touch `origin/main`); the lock is held only to point `origin/main` at it and merge. Hooks and writers never wait behind the network, and two overlapping fetches of `origin/main` (one of which fails with "incorrect old value provided") cannot happen. Needs git 2.29 or newer (`--no-write-fetch-head`, so the fetch does not rewrite the `FETCH_HEAD` that a concurrent `git pull --rebase` reads). Rules:

- **Resume.** The last synced `seq` is saved in `~/.local/state/tacit/follow.json` after each sync (the `seq` read before the fetch started, so a push that landed mid-fetch is synced again, never skipped). A restart sends it as `Last-Event-ID`. A reconnect in the same run sends the newest `seq` seen. If `: connected head=N` is below the saved seq, the server rebuilt its journal: take N and resync. If N is above it, a sync to N is owed even if no event arrives.
- **Reconnect.** Exponential backoff with equal jitter, 1 s doubling to 60 s (a server restart takes about 5 s; an outage costs one request a minute; the jitter spreads the machines that lose the feed together). The backoff resets after a stream stays up 30 s. A stream silent for 60 s (three keepalives) is dropped.
- **Fallback.** While the stream is down, sync every 60 s, so a broken feed leaves the clone at most a minute behind.
- **Verification.** The stream carries only journal rows, and a ref can move without one (the server dies between receive-pack and the journal append, or the journal is restored). While connected, every 5 minutes (288 small requests a day) the follower runs `git ls-remote origin main` and checks the answer is in the clone's HEAD. If the server is ahead it marks the clone behind and syncs. `verified_at` records the start of the last successful sync or check.
- **One follower per store.** An flock on `<state>.lock` refuses a second follower (exit 75) so two processes never overwrite one heartbeat. The state file is `follow.json` for the default clone and `follow-<hash of the path>.json` for any other store (`TACIT_STORE`).
- **Start-up.** A missing clone, an unreadable origin or a state directory that cannot be opened yet (a home not mounted at login) is waited out with the same 2 s to 60 s backoff, not an exit. Exit 78 (EX_CONFIG) means a bad invocation (unknown flag, bad `--as`, no key); the service unit does not restart on 78 and restarts on everything else, a Go panic (exit 2) included. Under launchd (`--launchd`) the 78 becomes exit 0, which KeepAlive does not restart (Install).
- **Auth.** None by default. A read-only clone made with `--as` signs each connection with that key (`tacit.as`, read at every connection, so a clone made after the follower started is picked up). `--as <harness>` signs explicitly.

`follow.json` is also the heartbeat. It holds `pid`, `store`, `seq`, `head`, `synced_at`, `verified_at`, `alive_at`, `connected` and `behind`. `alive_at` is stamped on connect, on every keepalive and after every sync, only while the stream is up and no announced push is unmerged (`behind` is false). `behind` is set the moment an event arrives and cleared by the sync that covers it.

### Skipping the SessionStart sync

The SessionStart hook skips its own network sync when `follow.json` says a healthy follower covers this clone: `store` equals the clone, the `pid` is alive, `connected`, not `behind`, `alive_at` at most 45 s old and `verified_at` at most 10 min old. 45 s is two keepalive intervals (40 s) plus 5 s for a loaded machine to write, and below the follower's 60 s silence timeout, so a half-open connection cannot look fresh for longer than it takes the follower to notice. 10 min is two verification intervals: if the follower cannot reach the server to check, hooks sync for themselves again after that. Any other state, or no file, and the hook syncs as before.

What the skip costs: a push from another machine can be invisible to this clone, and the hook will not sync, for up to 45 s after the follower's last keepalive (if the connection died silently) and in the normal case for the second or two between the push and the follower's merge. A push the journal never announced is invisible for up to 5 minutes (the next verification) and then synced. Before the follower, every SessionStart fetched, so it saw a push the moment it landed. Measured 2026-10-10 on the workstation at load 47, three separate runs each: `tacit hook session-start` took 381 ms (363 to 391) with the network sync and 31 ms (16 to 31) with a fresh follower; with a push waiting the synced path took 1346 ms (1299 to 1907), because the hook then also merges and builds the index.

## Git evidence

`client/internal/gitev` reads git as evidence about facts, without a model. From facts it takes the repos they are about (`projects/<repo>` scope, `applies_to.repos`, or a repo named in the text; each must be a git checkout under `$TACIT_PROJECTS`, default `~/projects`, worktree copies `wt-*` excluded; for a name in `ordinary_names`, see Derived facts), at most three, and the subject terms: what the writer put in `applies_to` first (symbols, paths, command paths and flags), then backticked paths, flags, snake_case and environment names from the text, then bare ones. Generic words are never terms, and a term found in 26 or more files at HEAD is dropped as not distinctive.

For each repo it reads, with a timeout per command and read-only (no locks, no writes, and a partial clone's missing files are not fetched: `GIT_NO_LAZY_FETCH`, which needs git 2.44, so with an older git a partial clone is skipped with a note), the commits on the subject (`git log` by path, `-G` by identifier, `--grep` by message) from 14 days before the older fact to HEAD, and what HEAD holds (a named path or identifier present or gone). It keeps at most two commits of context before the older fact and the first and last few after it, and counts the rest. Each commit carries author, committer and `Co-Authored-By` identities. The facts' own dates join the same timeline: the newest date in a fact's text (when it says it is from), its source note's date, its `created` (for a curator fact, the day it was filed, not the day it was true) and its first and last commit in the store.

Git is strong evidence for what happened and what the numbers were; newer commits often supersede an old result. It is never a replacement for an owner ruling: the committer is usually the main agent or a subagent. Every text it reads from git or takes from the facts is redacted with `digest.RedactAll` in one call before any of it is clipped or laid out, and the structured `Evidence` is redacted the same way; if redaction fails there is nothing to return. A read that fails or runs out of time is marked incomplete, shown with a note, and never cached or remembered; a term whose search failed is neither present nor absent. Per-repo results are cached by the commit they were read at and the subject searched, in `~/.cache/tacit/timeline` (at most 4000 files, the oldest removed first). `--as-of` replays: repos are read at the last first-parent commit before that time, and fact dates and the store history are cut at it. A timeline also carries `summary`, a few plain sentences built from the structured evidence after redaction (what the facts name that no repo holds now; per repo how many commits since the older fact touched the subject and the latest one's date and subject, or that nothing did; the repos that could not be read; a partial read says so), which the owner's pages show above the folded events. The review page shows the timeline under each finding (`GET /api/timeline`, same token as a mark; a server-side timeout answers 504 with a message, and the page treats any body without events as an error); `tacit timeline` prints it. As verifier input it did not beat the baseline, so `tacit verify` does not send it for pairs (eval/VALUE.md); a stale finding carries it, since the commits are the finding (see Staleness check). The package also reads one fact alone: `Effective` (its date), `ReadSince` (the light read: only specific identifiers; the paths and identifiers HEAD no longer holds; for each gone path its newest commit, for the gone identifiers the commits since a date that removed or rewrote a line holding one, at the repo's default branch, by committer date; its texts are raw, and the caller redacts what it keeps with `RedactAll` before clipping it) and `BuildOne` (its timeline).

## Index

`MEMORY.md` is generated by `tacit index`: one line per non-superseded, non-retired curated fact, grouped by scope, `- [name](path) - description`, sorted by scope then name. Inbox facts are not indexed. The curator regenerates it on every run, so no two writers ever edit the same file.

## Import

`--host` must be a slug; import refuses anything that would resolve outside `inbox/import@<host>/`. Symlinked source files are skipped. Loading walks skip symlinks, dot directories and `keys/`.

`tacit import claude <memory-dir>...` reads Claude Code auto-memory files (frontmatter `name`, `description`, `metadata.type`, `metadata.originSessionId`, `metadata.modified`) and writes each to `inbox/import@<host>/<origin>/<slug>.md`, where `<slug>` is the source file stem slugged (links between memories point at stems, so the stem is the identity; the source's own `name` field is not used) and a second stem that slugs to the same name gets a short hash suffix, with `type: unclassified`, the original type kept as `source.original_type`, scope guessed from the origin directory (`-home-alice-projects-myrepo` becomes `projects/myrepo`, `-home-alice` becomes `user`), `source.kind: observed` (`user` only when the original type is `feedback` and a quoted phrase of it is their words, with the evidence; see Rulings), `source.imported_from` set, `created` from `metadata.modified` or the file mtime. `MEMORY.md` indexes are skipped. A source file without frontmatter is imported with `name` from the file stem and `description` from its first non-empty line.

`tacit import codex <memories-dir>` splits `memory_summary.md` into one fact per bullet (sections `User preferences`, `General Tips`; the `User Profile` paragraph becomes one `user`-scoped fact `codex-user-profile`), `name` as a slug of the first words plus a short hash so re-imports are stable, `source.original_type` the section name slugged, `source.kind: user` for preferences and the profile only with a quoted phrase of their words (see Rulings), else observed. `rollout_summaries/` and `raw_memories.md` are session material, not facts, and are skipped.

Import is idempotent: the destination path is a function of the source, and an unchanged source rewrites an identical file.

Import never writes outside `inbox/`.

## Situation match (push mode)

A fact matches a situation when any of its `applies_to` lists matches: a path glob matches the file being read or edited (repo-relative), a `symbols` entry equals a symbol in the edit, a `repos` entry equals the current repo, a `hosts` entry equals the current host, or a `commands` entry is a prefix of the command about to run. Facts with an empty `applies_to` are pull-only.
