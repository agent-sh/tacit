Tacit keeps memory for coding agents in Markdown and git. Use a local store or share one across machines.

This release lets agents close the questions they can prove, so fewer wait on you. Every write tacit makes now masks the text it adds before it stages anything. It also adds `tacit links --restore`, which puts back the links to what a fact replaced that older runs unwrapped, and the event reader counts the lines it cannot parse.

- **Agents close the questions they can prove.** A question is what tacit leaves for you to answer: an agent's ask on a finding or query on a pair, the rotation's `check?` on one of your facts, or the reviewer's question about an agent's note. Two ways now close one (SPEC "Closing questions", #97).
  - **Moot, by code.** When a fact an agent's ask or query is about was retired, replaced by a third fact or is gone, `tacit verify` closes the question before it sends anything, with the reason. A pair whose replaced fact has a live successor is raised again on the live facts, for the verifier. `tacit questions moot [--dry-run] [ID...]` runs this on its own. A store whose facts do not read closes nothing.
  - **Proved, by an agent.** `tacit questions close ID --harness H --answer A --proof git|file|config|words|gone --evidence E --reason R [--words W [--from REF]]` closes a question an agent can prove. The answers: `keep:<fact>`, `both` or `neither` on a pair; `current` or `retire` on a stale finding; `current` only on a `check?`; `holds`, `wrong` or `moot` on a reviewer question. A `words` proof is your own words, which code finds as a statement of yours in your turns. A closure writes as the curator, so it runs on a machine that writes as the curator. `--dry-run` runs every guard and writes nothing. `tacit questions` lists what is open, and says which questions are yours and which ones code closes.
  - **What a closure may not do.** A closure never changes your ruling. It retires a fact that holds your words only on your own later words on the same subject. It never answers a question you marked, reopened, kept a fact of or left a note on. On the rotation's `check?` it may only say your fact still holds, never retire it. On a reviewer question your answer comes first: one you gave in a session the question was put in or in the rulebook pane keeps every agent from closing it.
  - tacit app and the review page show each closure with who closed it, the answer, the proof, the reason and the question it closed. Change this answer puts back what it changed, as it was, and the question is yours from then on.
- **Every write tacit makes is masked.** On 2026-10-27 a curated fact held a loopback llama-server key. The 2026-10-26 rebuild's curator had split an imported memory that came into the inbox unmasked, and nothing between the note and the push masked what the curator wrote. The key was a dummy; a real one would have gone the same way. Every client write now masks what it adds before it stages anything (`store.Store.commitPush`, #93).
  - In a fact, a note, a record or an overview: the description when the write changed it, the commands it adds (`applies_to.commands`, a record's `commands`) and the body lines the file at HEAD does not hold, each with the line before it as context.
  - In a review file: its added lines. In a ledger: the string values of the lines it adds that are prose.
  - The mask leaves what the file already holds at HEAD, frontmatter names, sessions and dates, a `[[link]]`'s target when it is a fact's name, your recorded words and the generated indexes. Your own text from tacit app is not masked. A write that masked something says so on stderr.
  - When the mask changes a fact, or a commit names an index while the clone holds a fact the commit does not carry (a killed batch's leftover), the indexes are written again from the facts the commit holds.
  - A write whose mask cannot run is refused before anything is staged. That covers no scrump, a failure, a short or reshaped answer, a redactor that does not mask the canary riding with each batch, and a file with a NUL byte.
  - Every commit names its files, so what someone else staged in the clone stays out of it. A commit made in the clone by other tooling is pushed as it was made, and only the server's scan checks it.
- **`tacit links --restore` puts back links to what a fact replaced.** Runs before v0.9.17 unwrapped such links as dead. `tacit links --restore [--dry-run]` puts them back through the step's locked write, in one commit gitev reads as a repair, so no fact's date moves (#96). Any other link an older run unwrapped stays as the run left it. The daily step runs as before. On the author's store the dry run finds 20 links in 5 facts.
- **The event reader counts the lines it cannot parse.** `State.Unparsed()` counts, from the session's start to its cursor, the lines that are not JSON, whose record does not decode where their kind is read, or whose message content is neither a string nor a list; in Hermes, the assistant rows whose tool calls do not decode. The saved State keeps it (version 2), and the `client/pkg/evidence` facade exports it (#94). A field of another type that a line's kind does not read no longer drops the line. On the author's machine the newest transcripts of each source (1,371, up to 400 a source) and the 400 newest Hermes sessions hold none.

Upgrading: no index, store format or server change; the server needs no deploy. Install it on every machine that writes to the store, since an older client writes without the mask. Every machine that writes now needs scrump on PATH: with none, or one that does not mask the canary, a write that adds text is refused and nothing is staged. The release archives bundle scrump 0.2.0, a source build needs it too (docs/portable.md, Redaction), and `tacit doctor`'s `scrump` check shows whether it masks. Then run `tacit links --restore --dry-run` and `tacit links --restore` once, on the machine that writes as the curator. An older client reads an agent's closure as an agent's mark, without its proof, and the curator's moot closure as a moot record; it passes over the reviewer-question records. A program that reads sessions through `client/pkg/evidence` gets `Unparsed` once it requires the client module at this release's commit. A State saved before this release loads as a bare cursor: its next read passes once over the lines before the cursor and counts them. At a session's end a bare cursor is now read with that pass too, so keep the State a read returns; `ReadFile` and `ReadHermes` still read nothing there.

Builds for Linux, macOS and Windows on amd64 and arm64 include the CLI, the browser app and a compatible scrump redactor. Git 2.29+ is required. [Setup and platform validation](https://github.com/agent-sh/tacit/blob/main/docs/portable.md).
