# Client reference

Every command, what it writes and where. The contract behind each one is in [SPEC.md](../SPEC.md).

## Build

`cd client && go build -o ~/.local/bin/tacit ./cmd/tacit` on Linux or macOS. See [portable setup](portable.md) for Windows builds, configuration, scrump and native job installation.

Choose a local store with `tacit init`, or a shared store with `tacit clone`. Local mode commits to this machine, needs no server or keys, and supports search, agent writes, owner edits and model jobs. The optional settings file selects paths, owner names and models; `--config FILE` selects another file. The commands below describe shared behavior where they mention a server, enrollment or pushing.

- `tacit init [--store DIR]` creates a local store. Put a custom path in the settings file or environment for later commands. `tacit sync` rebuilds its index without network work.
- `tacit maintain [--env-file FILE]` runs curation and verification manually. `tacit install curate [--env-file FILE]` prints native commands for a daily job.
- `tacit clone <url> <harness>` once per machine; `tacit sync` fast-forwards and refreshes the FTS index (`~/.local/state/tacit/index`). `tacit clone --read-only [--as reader] <url>` clones a copy that never pushes (no inherited credential helper, a push URL git cannot use); `--as reader` signs every fetch with the reader key, which the server's public path asks for. On such a clone nothing writes the store: `tacit add` and the MCP tool write to this machine's local overlay instead (`~/.local/share/tacit/local`, redacted, read by search and the hooks with the clone, marked `(this machine)`, never pushed), and the app's and the review page's marks and edits, `tacit dream`, `tacit import`, and the curator's steps (`curate`, `verify`, `stale`, `links`, `derive`, `results`, `resolve`, `rulings audit`, `review apply`) each refuse before any work, so nothing is computed, called, written or committed and the clone keeps syncing. Their `--dry-run` and `--out` modes, which write nothing to the store, still run. `tacit install dream` refuses a read-only clone. Sync, the follower, the hooks, search and the app's views work as on any clone. With `local_layer: on` (or `TACIT_LOCAL_LAYER=on`) such a clone dreams and curates its own sessions instead, into its overlay only (below).
- `tacit install claude` adds the hooks: SessionStart on startup only (after a bounded sync: up to 10 facts for the repo and host, owner rules first); UserPromptSubmit (up to 3 facts above a match floor, plus one owner rule (a ruling not given inside its task) when the three hold none, each fact once per session, nothing on harness-injected turns or prompts under two searchable terms; and, when the transcript's undreamed part has reached about one dream window (4 MiB of a Claude Code transcript, 1 MiB of a Codex one), it starts `tacit dream --session <transcript>` detached: a stat and a read of `dreamer.json`, about 3 ms); and PreCompact (`hook pre-compact`: starts the same detached dream and returns in milliseconds, so the session's facts reach the store for other and later sessions). Nothing is re-injected into a session after its compaction: the compaction's summary carries what the session had, the start block included. On a read-only clone or a machine without the dreamer's key no hook starts a dream, unless the clone's local layer is on. All fail open. It also registers `tacit mcp --harness claude` as the `tacit` MCP server in Claude Code's user scope (`mcpServers` in `~/.claude.json`, where `claude mcp add -s user` writes). Other servers and settings stay as written, the file as it was is kept in `~/.claude.json.tacit-backup`, and a rerun changes nothing. A server named `tacit` that does not run `tacit mcp` is left alone and the install stops. The SessionStart block then says `mcp__tacit__tacit_fact` for detail, in place of `tacit fact <name>`. In a session the agent reads one fact in full with `tacit_fact`, searches the store with `tacit_search` before an unfamiliar or risky step or when the hook's lines do not cover the task, and records a durable fact with `tacit_add`. The tools cost prompt tokens in every session: measured with `claude -p` on Claude Code 2.1.303, 43 input tokens while Claude Code defers MCP tools (its default: only the names are listed, and the agent loads a schema with ToolSearch), and 799 with tool search off (`ENABLE_TOOL_SEARCH=false`). `tacit install claude --no-mcp` installs the hooks only and removes the server.
- `tacit install codex` adds the same hooks to `~/.codex/hooks.json` (Codex 0.162 has the same UserPromptSubmit input, with `transcript_path`, and the PreCompact event) (Codex takes the same hook JSON and adds plain stdout as context); Codex skips new hooks until the owner trusts them once in `/hooks`.
- `tacit install hermes` installs a Hermes memory provider (`~/.hermes/plugins/tacit`, set `memory.provider: tacit`): the start block, the per-prompt facts through the same hooks (with the Hermes session id, so the window trigger can start a dream of the session at 120,000 bytes of new message content), the PreCompact hook from `on_pre_compress` (a dream of the session by its id), and Hermes' own memory writes mirrored into `inbox/hermes@<host>/`.
- `tacit install grok|pi|muse|agy` prints the MCP setup for `tacit_search`, `tacit_fact` and `tacit_add` through `tacit mcp --harness <h>`. agy uses its native registration command. Grok ignores what start and prompt hooks print, so MCP is its only path.
- Every write through `tacit add` and the MCP tool is redacted by scrump before it touches disk, and fails closed without it. A shared-store harness writes with its own key (`tacit keygen <harness>`, enrolled on the server). Local stores need no keys.
- `tacit follow` (shared stores only; systemd, launchd or Task Scheduler): holds the server's change feed (`/events`) and syncs the clone and its index within a second or two of each push. It resumes from a saved seq, reconnects with backoff, checks the clone against the server every 5 minutes, and needs a reader key on the optional public path. Local mode has no feed; skip this job. While its heartbeat (`~/.local/state/tacit/follow.json`) is fresh and recently verified, the SessionStart hook skips its own network sync (381 ms to 31 ms on the workstation); without the follower the hook syncs as before. Install with `tacit install follow` and run the native commands it prints (see [portable setup](portable.md)). On Linux it writes `~/.config/systemd/user/tacit-follow.service`, then `systemctl --user daemon-reload && systemctl --user enable --now tacit-follow.service`. Needs git 2.29 or newer. On a headless machine also run `loginctl enable-linger $USER`, or the service stops when the last login session ends.
- `tacit search`, `tacit fact <name>`, `tacit add` for humans and scripts.
- `tacit keygen <harness>` (shared stores only) creates `<harness>@<host>`; enroll the printed line on the server. Pushes sign with the writer's key (`TACIT_WRITER`).
- `tacit dream` (timer every 4 h): transcript deltas since the last run, from Claude Code, Codex, pi (`~/.pi/agent/sessions/*/*.jsonl`, or where `PI_CODING_AGENT_DIR` / `PI_CODING_AGENT_SESSION_DIR` point; the glob does not reach a subagent's `<session>/tasks/`, which is what keeps subagents out; a headless pi run's prompts are not the owner's) and the Hermes store (`~/.hermes/state.db` when it exists, read-only, owner sessions only; `hermes_db: off` or `TACIT_HERMES_DB=off` turns it off; see SPEC.md "Dreamer sources") (at most 4 MiB per transcript per run; the rest waits for the next run, and a complete line longer than that is passed over and counted in `dreamer.json` `skipped_long_lines`), digested, a model (`$TACIT_DREAM_MODEL`, generic default `opus`) extracts facts into `inbox/dreamer@<host>/`. A 60k-character window costs about $0.27 with Opus 5.5 ($0.12 Sonnet, $0.02 Haiku), so a run at the `--max-calls` cap (40) is about $11; the history measured in eval/VALUE.md came to about $79 a month with the Opus curator. Notes dreamed before prompt v5 (2026-10-18) carry no quote of the owner and curation files most of their rulings as observed; the dreamer does not go back over transcript it already read. The generated dream and curate jobs read `~/.config/tacit/env`: a background job does not inherit the shell's variables, and the selected runner needs whatever its provider needs (for Bedrock, `CLAUDE_CODE_USE_BEDROCK=1`, `AWS_REGION` and a profile or keys). The model variables (`TACIT_DREAM_MODEL` and the rest, see the README) go in the same file. `tacit install dream [--env-file F]` writes `tacit-dream.service` and `.timer` (the copies in `client/deploy/systemd/`) on Linux, a launchd agent on macOS, and Task Scheduler XML on Windows. On macOS and Windows `tacit dream --env-file F` reads the file itself. Local jobs need no enrollment; shared jobs need the dreamer key.
- The idle job (`tacit-dream-idle.service` and `.timer`, `ai.tacit.dream-idle.plist`, the `dream-idle` task; written by `tacit install dream`): every 10 minutes `tacit dream --idle 20m` and then, whatever the dream's exit code, `tacit curate --quick --min-interval 30m`, at nice 19 and idle I/O. The dream takes only the sessions quiet for 20 minutes (a closed terminal, a crash or Ctrl-C fire no hook, so quiet is the signal) or whose new content holds a compaction; a session still being written is the prompt hook's (at a full window) or the 4-hour timer's. A transcript whose window failed waits 4 hours for the idle job and the hooks (the 4-hour run retries it), so a failing model call is not repeated every 10 minutes. The quick curate splits the notes added in the last day, judges their conflicts and pushes, with no derive, results, links or staleness step; it does nothing within 30 minutes of the last quick run, while another curate runs, or, quietly, on a read-only clone or a machine without the curator key, and only the full run counts a note's failure strikes. On a machine without the dreamer's key the idle dream exits 0 quietly too. One dream and one curate run at a time (`dreamer.lock`, `curator.lock`): an idle or session dream and a quick curate exit 0 with "busy"; the 4-hour dream waits up to 45 minutes and the full curate up to an hour. So a fact a session found reaches the next prompt of any session within about an hour of its window filling, its compaction or its going quiet, instead of up to 16 hours (4-hour dreams, twice-daily curation). Cost: eval/VALUE.md "Idle dreaming".
- `tacit curate` (daily, from a machine with model access): inbox notes to one-fact entries (`$TACIT_CURATE_MODEL`, generic default `opus`), owner rulings kept verbatim, each new fact checked against the closest existing ones for contradiction or supersession (contradictions go to `review/<date>.md`), index regenerated, pushed as `curator@<host>`. Before the split, a pending note that only restates a curated fact or an earlier note (most terms shared and no number, path or dotted name the fact lacks; never their words against an agent's paraphrase) is set aside without a model (`restated` in `curator.json`). After the split, an entry that only restates a live curated fact of its scope, or an entry of its batch, is not written: its note is recorded as absorbed by that fact (`absorbed` in the run's report; a ruling only against a ruling with the same quote). A run starts at most `--max-batches` (16, about 85 dreamer notes and $0.91 each with Opus 5.5; a batch with an invalid answer is split in two and the halves do not count, see SPEC.md Rulings) and starts none after `--budget` (2h30m). A batch whose conflict check cannot run is not written and the run fails; `tacit curate --recheck-conflicts --since D [--until D] [--dry-run]` runs the check again for the facts made in those days. `tacit curate --quick` is the idle job's run (above); a full run waits for a quick one to finish.
- `tacit derive` (also the last step of `tacit curate`, so the daily timer runs it): no model. For every repo with a curated `projects/<repo>` scope and a checkout under `$TACIT_PROJECTS` (default `~/projects`), writes `derived/<repo>/<repo>-hot-spots.md` (the files most often changed in the last 400 code commits, with the files that change with them) and `<repo>-module-map.md` (layout, one line per directory), `derived_from` the commit it read: the remote default branch of the checkout (`origin/main`), else its HEAD, and the body says which. Same commit, same bytes, nothing rewritten; repos that vanished are retired, by the host that produced them. The facts are computed in memory and written under the store lock after a sync, so an interrupted run leaves the clone clean; one refused repo does not stop the others. `--dry-run` reports only, `--out DIR` writes the tree to DIR and lints it without touching the store (neither, nor `curate --dry-run`, fetches), `--repo R`, `--force`, `--take-over` (rewrite or retire another host's facts), `--no-fetch` (skip the one-branch fetch that precedes each read; it moves only a remote-tracking ref, 30 s timeout), `--set-branch <repo>=<branch>` (read that repo at a branch other than the remote default, kept in `~/.config/tacit/derive.yaml`), `-v` prints the facts. Never at SessionStart; the prompt hook adds at most one when the prompt names a file in it; `tacit search` and the MCP tool include them.
- `tacit stale` (also the last step of `tacit curate`): no model. Lists the curated facts whose subject changed in git after the day they were last current, as `stale?` findings in `review/<date>.md`: a file the fact names is gone, or an identifier it names was removed and no file of the repo holds it any more. Touching a hot file, adding a caller, moving a line or rewriting one whose name stands does not count. It flags, it never retires; `tacit verify` and the review page settle each one (still true, outdated, a detail to fix, or a question for the owner; an agent never retires a ruling). `--dry-run` prints what it would flag, `--budget` bounds the time (the facts not reached are first next run, and a fact whose read keeps not finishing waits longer each time), `--max` caps the findings per run. It reads each repo at the branch derive reads it at, not the checkout's, runs last in `curate` with its git commands at nice 19 and idle I/O, and is skipped by `curate --dry-run`. Rules: SPEC.md "Staleness check".
- `tacit links` (also a step of `tacit curate`, after derive and results): no model. A `[[link]]` in a curated fact that names no fact becomes `[[the one live fact that clearly answers to it]]` (the live end of a `superseded_by` chain, or the target spelled as a fact name) or, when nothing clearly does, plain text (`[[keys]]` becomes `keys`). A repo name is not a fact, so it becomes plain text. An owner ruling is never edited: it gets one `LINK?` line in `review/<date>.md` per dead link. Inbox notes and generated facts are not touched, nothing else in a repaired file changes, and the repair does not move the fact's date for the staleness check. `--dry-run` prints what it would do. Rules: SPEC.md "Link repair".
- The local layer (`local_layer: on` in the settings file, or `TACIT_LOCAL_LAYER=on`; off by default; read-only clones only): `tacit dream`, its idle and session runs, and the hooks that start them dream this machine's transcripts into the overlay's `inbox/dreamer@<host>/` (redacted, same cursors, locks and backoff as the store's dreamer). `tacit curate` and `curate --quick` turn those notes into facts under the overlay's `curated/<scope>/` with the store curator's split, rulings check, dedupe and conflict judge. The rulings check reads the owner's turns on this machine only, and a local fact that passes it is a `RULE` line here, marked `(this machine)`. A verdict about a store fact is a line in `curated/review/<date>.md`, never a change to the store; the whole-store steps (derive, results, links, staleness, the verifier) do not run. Nothing is written to the clone and nothing is pushed: the overlay never leaves the machine. `tacit install dream` on such a clone writes the dream and idle jobs and a daily `tacit curate` job (`ai.tacit.curate-local` on macOS, `tacit-curate-local.timer` on Linux), each carrying the setting. Rules: SPEC.md "Local layer"; cost: eval/VALUE.md "Local layer".
- `tacit dedupe [--dry-run] [--json FILE]`: no model. Curated facts that only restate another live curated fact of their scope (the rule the curator applies at the split) get `superseded_by` the fact kept, in one curator commit; the kept fact is a ruling first, then one with owner evidence or words, then the one with the most `applies_to`, then the newest. It refuses on a read-only clone. Rulings, facts with the owner's words, `system` facts and facts with an open conflict are never retired. Run `--dry-run` first: it lists each cluster and changes nothing. `tacit resolve clear <name>` undoes one. Rules: SPEC.md "Near-duplicates".
- `tacit verify` (daily, right after `tacit curate`): a model with read-only tools settles each open finding against its sources (repo code, git, docs, the machine) and marks it with its evidence, or leaves the owner one question when no source settles it. Its runner, model, effort and fallback come from the operator's private configuration. The generic defaults are Claude `opus` with `sonnet` fallback. Each verdict records the answering runner/model/effort. Refusals, invalid output and access-denied responses fail the batch. `--model` names one model and turns fallback off. `TACIT_VERIFY_ROOTS` adds read-only source directories (separated like `PATH`); each must exist. Claude auto-memory for the projects root is read when present, and is optional on a fresh install.
- `tacit review`: a local page (127.0.0.1:7448) that shows the owner only what needs them (Needs you), and every agent mark with its evidence. Keyboard first: ← keep left, → keep right, s both stand, q flag conflict, z reopen. Each mark sets the pair's relations, appends `review/decisions.jsonl` and pushes as curator.
- Under each proof the review page shows what git says: the facts' own dates, the commits in the repos they are about (`$TACIT_PROJECTS/<repo>`) that touched what they name, and what HEAD shows now. Built without a model by `client/internal/gitev`; `tacit timeline [--as-of T] <id>...` prints the same lines. Git settles what was built, measured or removed, never an owner ruling.
- `tacit app`: a desktop window (Wails v2 on the system webview: WebKitGTK 4.1 on Linux, WKWebView on macOS) with three views. Needs you: everything waiting on the owner (open pairs, stale checks, newer results, ruling changes, agents' questions, and the dead links in their rulings, which the review page leaves in the files), with the review page's marks. Facts: search (full text, prefix as you type) and filters by scope, repo, type, source, status and rulings only; a fact shows its body with clickable links, frontmatter, what links to it, the store's history and what git says, and can be edited (description, body, scope, type, applies_to), retired, restored, and its last edit undone. Inbox: what agents wrote and the curator has not read, read-only, with Promote as my ruling. New ruling (n) writes the owner's own words as a `user_standard` with `source.kind: user`, scope narrowest first. Every write is one commit through the store lock, linted (a new finding refuses it and keeps the draft), pushed as curator, subject `owner: ...`. Keys: 1 2 3 views, n, /, j k, e, r, u, p, ctrl+enter, esc. The window needs its own build, kept apart from the `tacit` the hooks run because it links GTK and WebKit (124 shared libraries; process start 41 ms against 12 ms, medians of three launches of 20 runs on a loaded workstation):
  `cd client && go build -tags desktop,production,webkit2_41 -o ~/.local/bin/tacit-app ./cmd/tacit` (Linux, needs `libgtk-3-dev` and `libwebkit2gtk-4.1-dev`), or `-tags desktop,production` on macOS (Xcode command line tools; add `CGO_LDFLAGS="-framework UniformTypeIdentifiers"` on SDKs that ask for it). Then `tacit-app install app` writes `~/.local/share/applications/tacit.desktop` and its icon on Linux, and `~/Applications/tacit.app` on macOS (see Mac). `tacit app --browser` serves the same page on 127.0.0.1:7450 behind a token, from any build. Rules: SPEC.md "App".
- `tacit review apply VERDICTS.json...`: apply a verifier's marks in one commit.
- `tacit resolve supersede <old> <new> | conflict <a> <b> | clear <name>`: the same answers from the command line.
- `tacit lint`, `tacit index` (MEMORY.md and the folder indexes), `tacit import claude|codex` for store maintenance.
- `tacit tree [--depth N] [path]` (and the MCP `tacit_tree`): the folder indexes from a folder down N levels, for this session's scopes.

## Mac

A Mac gets the same client with launchd in place of systemd. For local storage use [portable setup](portable.md#linux-and-macos): `tacit init`, harness installation and optional dream/curate jobs. Local app writes need no curator key.

For a shared store, one script does the first run and every rerun:

```
git clone https://github.com/agent-sh/tacit ~/projects/tacit
~/projects/tacit/scripts/mac-setup.sh --server <URL the Mac can reach>   # writer: hooks, follower, app, keys
~/projects/tacit/scripts/mac-setup.sh --read-only --server <public URL>   # off the tailnet: public path, reader key, nothing pushed
```

**A Mac that cannot join the tailnet (read-only).** `--read-only` reaches the server's public path, for example `https://tacit.example.ts.net` (Tailscale Funnel; SPEC.md "Public path"), which asks a key on every request and never takes a push. The script creates `reader@<host>`, prints its enroll line for the server, waits until `tacit authcheck reader` passes, clones with `tacit clone --read-only --as reader`, and installs the hooks (Claude Code, Codex when present), the follower (signed with the reader key) and the app, view only. What the agents there add stays in the Mac's local overlay, shared by Claude Code, Codex and the rest on that Mac, never pushed. No dreamer for the store. To have the Mac dream and curate its own sessions into that overlay, set `local_layer: on` in `~/.config/tacit/config.yaml` and run `tacit install dream` (the local layer, above).

What it does, in order, stopping with the fix when a step cannot go on: checks macOS, git 2.29+, the Xcode command line tools (for the app) and Go; checks `<server>/healthz` (401 is the public path's answer, accepted with `--read-only`); builds scrump into `~/.local/bin` when its text profile is missing (needs cargo; pinned with `--rev` to the commit that added the profile, since no release has it yet); pulls and builds `tacit` and `tacit-app` into `~/.local/bin`; creates the keys (writer mode: `claude`, plus `codex` when `~/.codex` exists, plus `dreamer` with `--with-dream`; read-only: `reader`) and prints the enrollment line to run on the server (over `--enroll-ssh` when given); waits up to `--wait` seconds (900) until `tacit authcheck <harness>` passes for each (it asks receive-pack for its refs with the writer's token, as `git push` does first, or upload-pack's for the reader, and sends nothing), printing the server's own answer on every try and stopping at once when waiting cannot help (`host_mismatch`, another key enrolled, `403`); clones the store; then `tacit install claude` (and `codex`), `install follow` and `launchctl bootstrap`, `tacit-app install app`; and prints a status. `--dry-run` runs the checks and prints every change instead of making it. No sudo, no secrets printed. Options: `--server`, `--read-only`, `--with-dream`, `--env-file`, `--no-app`, `--repo`, `--ref`, `--wait`, `--enroll-ssh`.

- The follower is `~/Library/LaunchAgents/ai.tacit.follow.plist`: `tacit follow --launchd`, RunAtLoad, KeepAlive on a failing exit or a crash (ThrottleInterval 5 s, the unit's RestartSec), ProcessType Background, Nice 10, LowPriorityIO. It writes its own log, `~/Library/Logs/tacit/follow.log` (`--log`), at most 1 MiB plus one `follow.log.1`, since launchd rotates nothing; launchd's `follow.err.log` gets only start-up errors and panics. launchd cannot exempt exit 78 the way `RestartPreventExitStatus` does, so under `--launchd` a bad invocation exits 0 and is not restarted.
- The dreamer is opt-in (`--with-dream`, or `tacit install dream`): `ai.tacit.dream.plist` runs `tacit dream --env-file ~/.config/tacit/env` every 4 h (StartInterval; a run missed while the Mac sleeps runs on wake), Nice 19. `ai.tacit.dream-idle.plist` runs the idle job every 10 minutes through `/bin/sh` (`tacit dream --idle 20m --env-file F; tacit curate --quick --min-interval 30m --env-file F`), Nice 19; without the curator key the quick curate does nothing. The env file holds what the selected runner needs, for example the Bedrock variables (KEY=VALUE, chmod 600); the plist holds none. Shared-store curation and verification run on a machine with the enrolled curator key. This setup script does not install them. A Mac can run them with `tacit install curate`, including in local mode.
- Both agents get a PATH with the binary's directory, `~/.local/bin`, where git, scrump and the configured runners were found at install time, `~/.cargo/bin` and Homebrew's directories: launchd starts agents with `/usr/bin:/bin:/usr/sbin:/sbin` only. Reinstall after a tool moves.
- The desktop app is `~/Applications/tacit.app`. In a shared store, a Mac without `curator@<host>` sees the app and `tacit review` as view only; Go refuses writes before touching files. Read-only clones always refuse owner edits. Local stores allow owner edits without a key. The bundle holds `Info.plist`, a copy of `tacit-app` (Finder starts it with no arguments; from inside a bundle that opens the window), and `tacit.icns`, signed ad hoc with `codesign`. Rerun `tacit-app install app` after rebuilding. The icon is committed (`client/cmd/tacit/macos/tacit.icns`); `scripts/make-icns.sh` rebuilds it from `reviewui/icon.svg` with headless Chrome, ImageMagick and python3. The window's GPU policy is a Linux setting; WKWebView needs none.
- The default `tacit` is pure Go (modernc SQLite, no cgo) and cross-compiles: `GOOS=darwin GOARCH=arm64 CGO_ENABLED=0 go build ./cmd/tacit`. `tacit-app` links Cocoa and WebKit through cgo and builds only on a Mac.
- The key id is `<harness>@<host>` from the hostname. A Mac without a fixed `HostName` can take one from the network, which would change the id; the script warns and prints `sudo scutil --set HostName <name>` for you to run.
- Transcripts: Claude Code on macOS keeps the same `~/.claude/projects` and `~/.claude/history.jsonl`, the desktop app's sessions say `entrypoint: claude-desktop`, and Codex keeps `~/.codex`; pi and Hermes keep the same paths as on Linux. The owner-words corpus also treats macOS temporary directories (`/private/tmp`, `/var/folders`) as agents' working directories. The shared-store setup script runs neither the audit nor the curator. Local stores start with ruling proof enabled; shared unaudited stores still need the ruling audit on the curator's machine.

## Server

`server/` (Elixir 1.20, OTP 28). It listens on the host's tailnet IP, port 7447, plus the optional public path for signed readers on 127.0.0.1:7448 behind Tailscale Funnel, which `server/deploy/funnel.sh root@<host> on|off|status` turns on and off (off by default). Deploy with `server/deploy/deploy.sh root@<host>`; prove a deploy end to end with `server/deploy/proof.sh root@<host> <tailnet-ip> claude`.

Enroll a machine: `tacit keygen claude` prints `ssh-ed25519 ... claude@<host>`; on the server `bin/tacit_server rpc 'TacitServer.Auth.Keys.enroll("claude@<host>", "<that line>")'`. `tacit clone` sets the credential helper. For a clone made with plain git: `git config credential.helper ""` (resets global helpers such as `cache`, which would replay an expired token) and `git config --add credential.http://<tailnet-ip>:7447.helper "tacit credential claude"`.

Model jobs accept the global `tacit --runner TOOL` override. The optional YAML configuration selects runners and models globally or per role; see [model runners](portable.md#model-runners). Claude aliases in this reference are defaults only when that role uses Claude.
